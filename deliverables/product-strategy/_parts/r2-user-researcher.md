## ① 重建「为什么不愿游玩」的归因：建造者动机模型

### 1.1 需要解释的两个事实（且必须用同一个模型）

- **事实 A（历史）**：他是**第一重度玩家**——1915 回合、12 会话、每回合手写 66 字角色扮演散文（p90 126 字）、纯"继续"仅 1.4%。这不是浅尝，是**极深的创作投入**。
- **事实 B（现在）**：他不玩。A6「**不想玩，投入到了别的工程学和项目中**」；开放问题 1 转折点「投入到了别的工程和项目中，**且感觉到没有新鲜感**」；B7「玩的下去，自动代码搬迁到服务器后，**没有更新过功能。但我也没怎么玩**」。

任何"他懒 / 产品太难 / 延迟太高"的解释都无法同时容纳 A 和 B。**能同时解释两者的模型只有一个：他的游玩动机不是"消费/娱乐型"，而是"建造者型"。**

### 1.2 模型：**起念于关系，续命于建造，熄火于新鲜感耗尽**

| 阶段 | 驱动 | 证据 |
|---|---|---|
| **起念**（为什么做这个产品） | **关系需求**：想和喜欢的角色说话 | A5 排序第一 =「单纯想和某个 npc 说说话」；D1 旅程全程围绕"喜欢的角色" |
| **续命**（为什么能玩 1915 回合） | **建造者动机**（探索—验证—采集三位一体） | 见 1.3 |
| **熄火**（为什么现在不玩） | **新鲜感耗尽 + 建造动机转移** | 开放 Q1「没有新鲜感」；Q3「越深入开发这种时候越少」；A6「投入到别的工程和项目」；B7"不更新功能后也没怎么玩" |

### 1.3 「建造者动机」的三条腿——为什么它既是 1915 回合的燃料，也是熄火的开关

他的游玩行为，本质是**建造主循环的一个子程序**，由三种需求驱动，**三者全部依附于"建造"**：

1. **探索（exploration）**——"这个新媒介能做什么？"
   - A7 心流出现在「26 年 1~2 月，**早于 RPG 插件**，在最原始的完全依赖 prompt 工程的形式」→ 心流来自**发现媒介能力边界**，而非消费内容。
   - 开放 Q3：「被 NPC 意外到有过，但处于**项目早期或未深入研究插件时期，越深入开发这种时候越少**」→ **惊喜随"理解机制"而衰减**。这是模型的核心证据：**探索燃料 = 未知量；他越懂，燃料越少。**
2. **验证（validation）**——"我造的功能真的能跑吗？"
   - B7 的因果句是**铁证**：**开发活动停止（代码搬迁后不再更新功能）→ 游玩也随之停止**。→ **游玩与开发同频共振，是开发活动的伴生物。**
3. **采集（harvesting）**——"真实长会话里，下一步该造什么？"
   - 每回合 66 字的深度写作，产出的不只是娱乐，更是**产品该往哪走的素材**。这解释了"为什么能写这么多"——因为**写本身就在为建造服务**。

> **一句话模型**：**他的游玩是"建造循环的副产品"——它寄生在"探索新媒介 + 验证新功能 + 采集新素材"之上；当媒介被彻底理解、开发转移到别的项目、功能被冻结，这三条腿同时失去支撑，游玩就停了。** 玩 1915 回合与现在不玩，**不是矛盾，是同一动机在不同生命周期的两种表现。**

### 1.4 关键评估：**是的，他的游玩本质上是"建造的副产品 / 验证行为"**

证据链（三处独立互证）：

1. **M1 的自白**：「**我更在乎做产品的 KPI**」。而且他列出的**"玩游戏的 KPI"本身就带着建造者视角**——「能否**识别**出角色的出戏感」「能否**想出**新的剧情」：**"识别出戏感"是 QA 语言，"想出剧情"是内容策划语言。他的"游玩 KPI"其实是"研发 KPI"的子集。**
2. **C1 双榜第一 = "生成角色"**：最常用、且删掉最心疼的都是**创造角色**（造物），而非"和角色互动"。
3. **画像旁证**：产品自己的 `player_tendency_summary` **无法为开发者生成任何偏好画像**（占位"尚无明确倾向"），而所有真实玩家都有清晰画像；他 7 provider / 4 preset 到处换（**调参者签名**）。

### 1.5 这对「如何让他持续回来」意味着什么（直接结论）

- **不要靠"加内容"召回他。** A5 里"新角色卡/新世界观"只排在中游——内容更新对他有中等吸引力，**不是**"今天想打开"的冲动源。而且内容消费不是他的动机。
- **唯一能持续召回的，是"把玩重新接回造"**——让游玩持续产出建造价值（发现新惊喜 = 新产品灵感、验证新功能 = 发布前验收、真实长会话 = 内容素材）。**但这是"续命"，不是"治愈"**：一旦产品"造完"，游玩就会再次失去燃料。
- **真正能让他"想回来"的，是让"起念动机"（关系）第一次被真正满足。** M1 产品 KPI 前两条是「能否还原角色」「能否让用户感受到角色是**鲜活的、有个性的**」——这正是 A5 第一项"想和 NPC 说话"能成立的前提。
- **但这里有一个死结，也是全案最深的一条**：**作为作者，他无法被自己的造物打动**（Q3：越深入越少）。所以"让他回来"的前提是**让他重新变回"读者"而非"作者"**。开放 Q5 说他"几乎没有控制权"——**但那只是产品层的控制权；他真正缺的是"信息层的失明"——他不知道 NPC 下一秒会做什么。** → **NPC 能动性（会拒绝、会主动、会意外）= 让他重新成为读者的唯一途径**，也是①与④（关系深度）共同的解法。

> ⚠️ **必须标注的自述/行为冲突**：A2 自评「动机 10」、A5 自评"最想和 NPC 说话"，**但实测他不玩、也没把"说话"变成行为**。→ **说明瓶颈不是动机，是触发（福格 P=3）**：建造链的触发（bug、灵感、别人的项目）随时在线，游玩链的触发缺失。**"想玩"是愿望，"建造"是行为——两者背离，这就是全部真相。**

## ② 用 B2 成本表重构摩擦模型：从「延迟模型」到「认知负荷模型」

### 2.1 B2 的分数结构（负责人自述）

| 环节 | 分 | 我的解读 |
|---|---|---|
| 启动产品 | 1 | 低 |
| 选角色卡 | 1 | 低 |
| **等 LLM 首字** | **1** | **极低（与旧假设相反）** |
| 读输出 | 1 | 低（自评） |
| **想我接下来说什么** | **4** | **最高** |
| **中途出戏** | **4** | **最高** |
| 收尾结束 | 3 | 中高 |

**结构性事实：全部摩擦集中在"轮到玩家出手的那一刻"（构思 4 / 出戏 4 / 收尾 3），而所有"系统侧/被动侧"环节都是 1。** 这是一张**极其干净的负荷地图**。

### 2.2 为什么「等 LLM 首字」只有 1 分？（推翻"延迟是主要摩擦"）

四条理由，其中两条有硬数据：

1. **被动等待 ≠ 主动劳动。** 等首字时，大脑可以放空、喝茶、看手机——**认知资源占用 ≈ 0**；"想说什么"时，大脑满负荷运转。**摩擦不是用秒计的，是用"认知资源占用"计的。**
2. **数据佐证 1**：工具等待全量加权仅 **2.7 秒/回合**（不是"每回合等 60 秒"）——**等待在物理时间上本来就很小**，自评 1 分与之自洽。
3. **数据佐证 2**：相邻回合中位间隔 **266 秒（4.4 分钟）**——**这 4.4 分钟里，绝大部分花在"阅读 + 构思"，不是花在等待。** 玩家不排斥"慢"，玩家排斥"费脑"。
4. **活动性质**：这是一项**慢速、需专注的创作活动**。慢速是它的属性，不是它的缺陷。**把"慢"当问题去优化（如流式），是打偏了靶子。**

→ **结论：摩擦模型必须从"延迟模型"重构为"认知负荷模型"。** 延迟埋点失真 + 旧假设，曾把产品引向"优化等待"，而真正的痛点在"优化出手"。

### 2.3 为什么「想我接下来说什么」= 4 分？

- 这是**生成式劳动（generative labor）**：玩家不是"从选项里挑"（低负荷），而是**"从零构思下一幕"**（高负荷）。每回合都要求一次小型创作——66 字中位数就是这份劳动的产出。
- 这份劳动**不可外包、不可跳过**：他不写，故事就停。**他是唯一的发动机。**
- **B3 直接确认**：他选 **B（要我想接下来该说什么）**，而非 A（读后台刷屏）→ **"叙事空白"（没东西可接）比"信息过载"更劝退**。这同时**推翻了"后台日志刷屏是主要噪音"的假设**。

### 2.4 为什么「中途出戏」= 4 分？

- 本产品的**唯一回报就是沉浸**（没有分数、没有机制快感，全靠"我在一个活着的世界里"）。**出戏 = 回报瞬间归零。**
- 出戏的**来源**（对应已验证缺陷）：① `<xiaoai_core>` 泄漏 7.6%——机械 token 直接击穿第四面墙；② 编号选项合规率 44.9%——近半回合突然从叙事掉进"请选 1/2/3"菜单；③ 角色还原度崩（NPC 说了不像角色的话）；④ 逻辑矛盾 / 记忆丢失（E5：LLM 注意力涣散）。
- **出戏比等待更贵，因为不可逆**：一次出戏会污染后续信任（"它随时可能崩"）。等待可恢复，出戏不可恢复。

### 2.5 为什么「收尾结束」= 3 分？

- **产品没有"结束仪式"**：没有"本回结束"的自然收束点，玩家只能"腻到关掉"（负体验）或"舍不得但必须关"（3 分）。
- 结合 D4「想玩随时能玩」——**没有固定节奏 → 结束永远是"被打断"而非"完成"**，天然带未完成感。
- **注意**：这修正了我上一轮的"冷启动成本高"表述——B2 里"启动产品"只有 1 分。**真正的冷启动成本不是"打开"，而是"入戏的第一句"（=4 分的构思）。**

### 2.6 ★ 认知负荷的具体来源清单（B3 + B4 拆解）

B4 原话（移动区域时）：「我该思考在这个区域做什么，时间段切换是否合理，是否有新的角色，新角色出现是否合理，我该如何搭话」。加上 B3 的"我接下来该说什么"，得出一张**完整的负荷清单**：

| # | 负荷来源 | 性质 | 归属责任 | 证据 |
|---|---|---|---|---|
| **A** | **叙事方向生成**（"接下来该说什么/演什么"） | 无中生有的创作 | 本应 AI 提供骨架 | B3=B |
| **B** | **行为规划**（"我该在这个区域做什么"） | 目标设定 | 玩家（合理） | B4 |
| **C** | **世界自洽性校验**（时间段是否合理、新角色是否合理） | **元认知 / 编辑劳动** | **本应系统的世界模型保证——被转嫁给玩家** | B4 |
| **D** | **角色发现**（是否有新角色） | 扫描负荷 | 系统可代劳 | B4 |
| **E** | **社交发起**（"我该如何搭话"） | 社交脚本生成 | 可被 NPC 主动化消解 | B4 |
| **F** | **长文本阅读并保持连贯**（每回合 800~1160 字） | 持续负担（自评 1，但客观巨大） | 内容侧 | 实测输出量 |
| **G** | **后台状态追踪**（好感度/记忆） | 自评低——**因为不可见所以不占负荷，也因此"白费"** | — | 62% 记账不可见 |

**清单里最重要的一条是 C。** B4 里"**时间段切换是否合理、新角色出现是否合理**"——这两条本该由系统的世界模型保证，却变成了**玩家的检查项**。这是**产品把自己最核心的责任（世界一致性）外包给了玩家**。它是一个此前未被命名的、具体的、可修的负荷源。

> **优化靶心（可执行）**：摩擦应集中在**"减少玩家出手的认知劳动"**（A/C/D/E），而非"减少等待时间"。其中 **C（世界自洽性校验）与 E（社交发起）是产品最该立即接管的**——让系统保证世界一致、让 NPC 主动搭话，可一次性削掉两项负荷。

## ③ 核心矛盾的裁决：**「消费布景，即兴演出」**

### 3.1 矛盾陈述

- 开放问题 2 自述：「**我想消费一个写好的世界**」。
- 实测行为：他每回合写 **66 字**角色扮演散文（p90 126），纯"继续"仅 1.4%。
- 相关自述：E3 选 **A（按你说的演）**，但「**我想要新鲜感和意外感**」；E4「**存在且兼容的高自由度玩法的玩具，可以不按照固定规则玩**」。

### 3.2 明确结论（不给罗列，只给裁决）

> **他要的不是"读一个世界"（纯消费），也不是"写一个世界"（纯创作），而是：**
> **「在一个别人搭好、会给他意外的世界里，自由地即兴行动。」**
> **一句话：「消费布景，即兴演出」（consume the set, improvise the performance）。**

**"想消费"与"在深度创作"并不矛盾——因为它们在两个不同的层：**

| 层 | 谁负责 | 对应自述 |
|---|---|---|
| **世界观层**（设定 / 人物 / 氛围 / 走向骨架 / 意外） | **产品提供 → 他"消费"** | Q2「消费一个写好的世界」；E3「要新鲜感和意外感」 |
| **行为层**（自己怎么走位、怎么开口、怎么反应） | **他"创作"** | 66 字/回合；D1 旅程全是"我的行动"；E4「高自由度玩具」 |

他的 66 字**不是"写小说"（编剧），而是"在一个已搭好的舞台上即兴演出"（improv）**。证据：D1 旅程全程是"我探索 / 我遇到谁 / 我和谁发展 / 我与更多角色建立关系"——**全是"我的行动"，没有一句"我编写世界设定"**。

### 3.3 这个裁决如何解释 E3 的"既要控制又要意外"

E3 看似矛盾（选 A"按你说的演"= 要控制，却又要"意外感"）。**用"即兴演员"模型正好解释**：**演员控制自己的台词与走位（要控制），但需要对手演员（NPC）给他惊喜（要意外）。** 他要的不是"世界听他指挥"，而是"**我的表演自由，世界的反应不可预测**"。这正是"即兴"的定义。

### 3.4 E4 的"玩具"（toy）是关键补充——它解释了"为什么玩着玩着就不玩了"

E4 说的是**"玩具"（toy），不是"游戏"（game）**：
- **游戏**靠规则 / 目标 / 进度维持长期动机；**玩具**没有这些，靠"**发现它还能怎么玩**"维持。
- 玩具的动机是**探索性**的——一旦穷尽玩法（他完全理解了它），玩具就被放下。
- → **这与①的"建造者动机"完美闭环**：他把产品当**玩具**（探索它），所以**探索完就放下**。这也解释了 B6"想试新东西/新机制"是放弃的触发点之一。

### 3.5 产品形态结论（直接决定形态，务必采纳）

1. **世界 / 人物 / 走向骨架 / 意外 → 必须由产品提供。** 满足"消费"与"新鲜感意外感"。→ **否定"纯沙盒工具"路线**（把一切都交给玩家写，等于让玩家当编剧——他不要）。
2. **玩家在其中的行为 → 必须完全自由、无固定规则。** 满足"高自由度玩具"。→ **否定"TRPG 规则 / 掷骰 / 胜负"路线**（E2 明确"知道但嫌麻烦也没用"；E5 说"原始形态就是自由，但实际不允许"）。
3. **产品不应要求玩家编写世界（压低世界观层的创作负担），但必须在行为层留出无限空间。**
4. **过去矛盾的根源**：产品把两层混在一起——**既让玩家消费（读长文），又让玩家产出（构思剧情 + 校验世界自洽）**。矛盾不在需求，在**层次混淆**。

> **一句话给产品**：**把"创作负担"从世界观层移到产品；把"自由度"在行为层拉满。**

> ⚠️ **本路线的最大技术风险（E5 亲自指出）**：E5「原始形态就是自由，但**实际不允许。长期下来 LLM 注意力涣散**」。→ **自由度越高，LLM 越难维持长程一致性。** "即兴演出"路线的成败，取决于能否在"高自由"下保住"世界一致性"——**这正是"记忆保持"（D5 四大在意点之一）的技术战场。**

## ④ D1 旅程 × C6 好感度二极管：关系深度为何被系统伤害

### 4.1 D1 旅程里**没有任何机制**——这句话本身就是诊断

D1：进入世界探索 → 遇到喜欢的角色 → 与喜欢的角色深入交流发展关系 → 意外偶遇其他喜欢的角色 → 与更多角色建立关系。

- 旅程的驱动力是**"喜欢的角色"（情感引力）**，不是"攻略数值"。好感度、进化、伏笔、结算**一个都没出现在他的理想旅程里**。
- → **好感度系统不是旅程的一部分，它是旅程的"后台仪表盘"——而玩家从不看仪表盘。**

### 4.2 设计假设 vs 玩家实际行为

| | 好感度系统的设计假设 | 玩家实际行为（C6 原话） |
|---|---|---|
| 关系的本质 | **可攻略的曲线**（低→中→高，逐阶解锁） | **可拥有的联结**（到了就该是"拥有"的状态） |
| 乐趣来源 | **过程**（享受一点点把关系推上去） | **结果**（与喜欢的角色处于亲密状态） |
| 对"重来"的态度 | 可反复攻略 | **不喜欢反复攻略**（reset / 新群后仍锁满值） |

**冲突本质：系统把"过程"当乐趣，玩家把"结果"当目标。攻略曲线对玩家是"门槛"，不是"玩法"。**

### 4.3 ★ 实测佐证：二极管不是自述，是数据库里的客观分布

我对全库 `npc_player_affinity` 做了独立统计（n=125）：

- **29.6%（37/125）恰好等于 100（满值饱和）**；
- stage 分布：**「誓约」(最高) 45 + 「陌生」(最低) 39 = 84/125 = 67.2%** 挤在**两端**；中间阶段（友善 20 / 信赖 9 / 亲密 5）合计仅 **27.2%**；
- 负责人自己的 86 条好感记录里，**22 条（25.6%）为满值 100**，且存在 -70 / -60 / -15 等负值。

→ **「最高或最低才有明显区别，中间几乎看不出区别」被完全证实。** 这不是玩家的感觉，是**系统把"差异化预算"全砸在了两个极端，而玩家的实际停留点恰恰在中间**。**系统的"差异化投资"与玩家的"实际停留位置"完全错位**——这是好感度设计的根本错误。

### 4.4 对"关系深度"这一核心体验的伤害

1. **中间状态无差异化 → 玩家感受不到"我们正在一点点变近"的细腻过程**。关系深度本应由**差异化反应**体现（NPC 因关系不同而说不同的话），但中间带是"静音"的。
2. **满值 = 关系的死亡（体验层）**。一旦锁在 100，就**没有"更进一步"的空间**，NPC 行为不再随关系变化（已封顶）。**玩家要的是"一直有微妙的靠近感"，系统给的却是"到了就停"。**
3. **"不喜欢反复攻略"** 说明：玩家把关系视为**"已建立的资产"，不是"需反复维护的挑战"**。→ 与 D1 一致：旅程终点是"与更多角色**建立**关系"（建立，不是经营）。关系一旦建立，就该是"拥有"的状态。

### 4.5 本轮新增的两条未被简报覆盖的发现

- **【新矛盾 1】reset 对"关系体验"是破坏性的。** C6「即使是 reset、开了新群后**也是如此**」暗示：**产品缺少"重开世界但保留关系"的粒度**。玩家用 reset 是为了重开剧情，**不想重开关系**。→ 这是一个具体、可修的产品缺口。
- **【新矛盾 2】"差异化预算"与"停留位置"错位**（见 4.3）——这是比"二极管"更底层的设计错误：**不是"数值设计得不好"，而是"差异化的方向反了"。**

> **可执行方向**：关系的价值应体现在**"持续的、差异化的、不可预测的互动"**（NPC 有能动性、随关系状态说不同的话、会主动推进），而非**"数值阶梯"**。**要关系深度，就要让 NPC 随关系"演化出新的自我"，而不是让数值"爬满格子"。** → 这与①的"NPC 能动性 = 让他重新成为读者"是**同一条解法**。

## ⑤ 用 D5 判定工程缺陷：哪些"出戏"，哪些是开发者自娱

### 5.1 D5 给出的判定标尺（负责人自己的话）

> 「接受产品的不完美……**他们在乎的是情绪价值、陪伴体验、角色还原度、记忆保持**。」

**标尺 = 凡伤"情绪价值 / 陪伴体验 / 角色还原度 / 记忆保持"的，才是真伤；其余是开发者自娱。**

### 5.2 逐条判定表

| 缺陷 | 判定 | 理由 |
|---|---|---|
| **`<xiaoai_core>` 泄漏 7.6%** | **出戏（真伤）** | 机械 token 直接击穿第四面墙，7.6% = 每 13 回合一次，频繁到破坏信任。**但**：泄漏率由 provider 决定（GPT-5.5/deepseek-reasoner **0%**；siliconflow 26.1%）→ **本质是"provider 选择"问题**。玩家表现为"角色偶尔崩"，会自行归因"AI 抽风"（D5 的自我纠正）。→ **伤体验但玩家会自行消化，优先级中高（可修、直伤沉浸）。** |
| **编号选项合规率 44.9%** | **⚠️ 判定反转：不是缺陷，是"定位混乱的工程表征"** | **关键洞察**：这里 44.9% 的"合规"= 菜单化（"请选 1/2/3"），55.1% 的"不合规"= 纯叙事。**而玩家要的恰恰是纯叙事（E5 自由）**——所以**"合规率低"对玩家其实是好事**。根因是两个注入点互相抵消（contract_pipeline 要菜单 vs style-core 反菜单）。→ **这不是玩家在意的缺陷，是产品在"要不要菜单化"上自相矛盾。在"合规率"这个指标上优化 = 在错误的方向上努力（开发者自娱）。** |
| **工具错误 2.05%，100% 集中在 4 个 NPC 工具** | **半真伤（下游伤体验，但概率低）** | 4 个工具（`generate_npcs` / `sync_zone_npcs` / `mark_npc_evolution_trigger` / `update_npc_affinities`）**恰好服务"角色生成 / 演化 / 好感"——正是 D5 说的"角色还原度 / 陪伴 / 记忆"**。工具失败 → NPC 生成失败 / 好感不更新 → 伤体验。但 2.05% 极低，玩家大概率感知不到。→ **优先级中：下游影响恰是玩家在意的，但发生率低。** |
| **延迟埋点失真**（171 站点配对泄漏） | **开发者自娱（且对决策有负价值）** | 玩家零感知。**唯一影响：误导开发者优化错方向**（曾把流式当最高杠杆）。→ 对玩家零价值，**对产品决策负价值**。 |
| **审计只覆盖 narrator 阶段** | **开发者自娱** | 审计是开发工具，玩家不接触。但它造成"看不到非 narrator 阶段"→ 诊断偏差。 |
| **`TOOL_SKILL_MAP` 6 条映射指向不存在技能** | **判定取决于映射对象** | 若这 6 条指向**机制类**技能（E2 里被主动放弃的那类）→ 玩家根本不用 → **开发者自娱**。若指向**角色 / 陪伴 / 记忆类** → **真伤**。→ **需 data-analyst 确认映射对象属于哪一类。** |
| **`hooks.py` 新手引导只有一句话** | **对他无伤；对"小部分朋友"真伤** | 他不需要引导。但 D3 说产品要"扩展到小部分我认可的朋友"——**新玩家无引导 = 不知怎么玩 = 直接流失**。→ **优先级取决于"是否真要扩展到朋友"。** |
| **provider 混用 18 个** | **开发者自娱（间接真伤）** | 玩家表现为"体验时好时坏"（不同 provider 的泄漏率 / 质量差异大），会归因"AI 抽风"。→ 本质是**"开发者调参行为的副作用"**，玩家无感知，但伤体验一致性。 |

### 5.3 汇总判断

> **缺陷清单里，真正伤玩家的是"出戏类"（泄漏、角色崩）与"角色 / 记忆类"（NPC 工具错误、注意力涣散）；"工程类"（埋点、审计、映射、provider 混用）几乎全是开发者自娱。**

**而 D5 的原话已经给出了这个判定**——「工程上的不完美对他们而言不是什么问题」——**他只是没有把它应用到具体清单上**。

### 5.4 ⚠️ 一条必须提醒的反向风险

D5 说玩家"有很强的自我纠正和适应能力"——这句话**有双重危险**：

1. 它是对的：玩家确实容忍工程缺陷（长档 3931 回合是铁证）。
2. **但它可能被误读成"不必修 bug 的借口"。** **"能适应" ≠ "不流失"**：每一次"我又得自己脑补修复它"都在**透支沉浸预算**。
3. → **正确读法：工程缺陷不会立刻赶走玩家，但会持续侵蚀"情绪价值"的储备。不要用它来降低 P0 优先级。**

## ⑧ 一句话北极星（给产品形态）

> **他要的是一个「别人搭好、会给他意外、且他可以在里面自由即兴」的世界。**
> **产品要做的三件事：① 把世界 / 人物 / 走向的"骨架与意外"由产品提供（压低世界观层的创作负担）；② 把玩家行为层的自由度拉满（去掉规则 / 掷骰 / 胜负）；③ 把"轮到玩家出手"的认知劳动削到最低（系统接管世界自洽性校验与社交发起，NPC 具备能动性）。**
> **唯一能让他持续回来的，是让 NPC 真正"鲜活、有个性、会意外"——那既是他 M1 的产品 KPI，也是他 A5 的第一愿望，更是让他从"作者"退回"读者"的唯一途径。**
