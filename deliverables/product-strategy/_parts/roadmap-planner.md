## 第 1 部分 · 破局战略（先定方向，再定动作）

### 1.1 "破什么局"——三个候选病因的裁决

产品负责人的自述是"功能太多、效果不好"。但三位队友的证据指向**三个不同层级的病因**。我的裁决如下：

| 候选病因 | 证据强度 | 我的判定 | 理由 |
|---|---|---|---|
| **A. 功能太多（表面积过剩）** | 强【实测】 | **症状，不是病因** | 221 个功能面 / 94 配置 / 49 工具是真的多。但**竞析的关键判断成立**：SillyTavern 参数更多，却因为**把复杂度外置**（6 组件 + 社区卡库）而本体保持薄。→ **多不是原罪，裸露才是。** |
| **B. 方向错配 + 形态错配** | **最强（v4 已升级为实证）** | **第一病因** | **方向错配（工程层）**：产品把 ~26 个机制工具投在"战斗/冲突/成长"，而**产品自己的画像显示可被画像的 11 份实质样本中 9 份明确回避战斗/冲突**【实测·产品自证】。**形态错配（体验层）**：玩家以"舞台指令式"输入 + 读 800~1160 字散文使用，**输入输出比 1:14**，TRPG 机制**在真实用法里几乎不存在**。→ 产品被做成 GM 模拟器，却被当"自由文本场景导演器"用。 |
| **C. 没有反馈回路（不可见 + 零即时反馈）** | 强【实测】 | **第二病因（可并行修）** | 65.3% 调用玩家不可见；内容型功能全周期仅 10 次 = 0.17%；胜任感（SDT）**崩得最彻底且最可推广**——两人都无进度条、无反馈、无"我做到了"。 |

**裁决**：
> **破局 = 先做方向纠偏（砍/默认关闭战斗·冲突·成长机制层）→ 再把交互从"主导"改"包裹"→ 同步修反馈回路 → 最后用减法收拾表面积。**
> **⚠️ v4 修正**：原判"形态未定前任何砍留都是错的"仍成立，但**"形态"已被产品自己的画像部分回答**（9/11 回避战斗侧）→ 故"形态裁决"从"高优先级大动作"**降级为"1 天轻量确认（G 组验证画像）"**，而**"方向纠偏"升为第一优先级**——因为"默认关闭"是**可逆动作**，无需等待完整裁决即可执行。

**为什么"留不住人"不成立（v4 强化）**：**权威回合数合计 3931，单档最高 1062**（`game_sessions.interaction_count`，不受截断）【实测】。→ 产品**不是留不住人，而是留得极好**。真正的问题是 **"能玩 1062 回合，却下班不想打开"**——因为**冷启动成本高（决定"要不要开"）vs 持续成本低（决定"能撑多久"）是两种不同的成本**。且**"玩得长 ≠ 玩得爽"**：玩家每回合要**产出指令 + 承受超长阅读 + 维持叙事连贯**，三项都是认知成本，且**零即时反馈**。

### 1.2 产品定位的一句话收敛

**竞析给出的方向**：*"中文硬核 RP 的自托管 SillyTavern + 状态机"*。

**我的评估：方向认同 70%，但需要 30% 修正。**

| 竞析方向 | 我的评估 | 修正 |
|---|---|---|
| "中文硬核 RP" | ✅ 认同 | 中文 TRPG/跑团 AI 供给稀薄（aiga_ 以英文 Discord 为主），**差异化成立**【竞析】。 |
| "自托管" | ✅ 认同 | 自托管是 S 优势（数据自主、无审核、无厂商锁定），但**同时是 W 劣势**（无内容飞轮、无运营者）。 |
| "SillyTavern" | ⚠️ **部分认同** | 学它的**复杂度外置策略**（预设包/卡库可导入导出），**但不要学它的"前端容器"定位**——那是创作者工具，不是"游戏"。 |
| "+ 状态机" | ⚠️ **修正** | 状态机是**引擎长板**，但**当前它服务的是一个没人用的形态**。→ **状态机必须服务"可见反馈"，而不是服务"内部记账"。** |

**修正后的一句话定位**：

> ## **"一个开箱即玩的中文单人跑团——深度世界状态藏在引擎里，玩家第一分钟就看得见它。"**
>
> 拆解为三个必须同时成立的定语：
> 1. **开箱即玩**（StarterKit，94 配置 → 1 次选择）——解决"上手成本极高"。
> 2. **单人跑团**（不是"GM 模拟器"，也不是"纯文本导演器"，而是**"AI 提议 + 玩家点头/微调/否决"的包裹式叙事**；**规则重心在关系/日常/剧情，而非战斗/成长**）——解决"方向错配 + 形态错配"。
> 3. **深度可见**（关系图鉴 / 悬念卡 / 状态条，把状态做成卖点而非黑箱）——解决"65.3% 不可见"。

> **【裁决项·D3】** 如果他的答案是"这只是我的私人玩具"，则定位改为 **"一个我每天愿意打开 30 分钟的世界"**，路线图不变，但**放弃阶段三的社区化**。这个分叉决定 30% 的路线图。

### 1.3 分层目标（对齐竞析"哑铃形市场"）

| 层级 | 目标 | 判定标准 |
|---|---|---|
| **产品目标（本阶段）** | 把"深度状态"从**隐性成本**变成**显性卖点** | 玩家能**看见**世界在生长（状态条 / 图鉴 / 悬念卡） |
| **个人目标（本阶段）** | 让"下班后打开它"这个行为**真实发生** | 不重开的最长回合数↑；完整玩完的 session 数↑ |
| **市场目标（非本阶段）** | 卡位"中档空白"（有深度但开箱可用） | 阶段三才谈，**本阶段不投入** |

### 1.4 Non-goals（这个阶段坚决不做什么）

> 目的：**防止范围蔓延**——减法方案最容易被"顺手再加一个"毁掉。**这是本路线图的护栏。**

1. **🚫 不再新增任何 LLM 工具 / 配置项 / skill**（**红线**）。新功能上线前必须满足 **CDI 增量 ≤ 0**【data-analyst 建议闸门】。→ 把"加功能的冲动"导向"改暴露方式"。
2. **🚫 不追求"服务 100 个陌生玩家"**：D3 元问题裁决前，不投入社区 / UGC / 市场 / 多用户运营。
3. **🚫 不做移动端 / 云托管 / 服务器化**：本轮是本地插件的**内部精简 + 形态修正**，不改部署形态。
4. **🚫 不做多模态（TTS / 图像）**：只登记不排期（阶段三可选）。
5. **🚫 不砍"内容型功能"本身**（伏笔 / 记忆 / 委托 / 角色卡）：它们是**留存钩子**，本轮只改**暴露方式**（手动→自动）。
6. **🚫 不删 canonical 角色卡 / preset 内容**：内容资产是长板，只做"打包成 StarterKit"。
7. **🚫 不重写流水线引擎**：只做"二选一 + 隐藏"。
8. **🚫 不碰 NSFW 子系统**：真实用法强相关，保持现状。
9. **🚫 战斗/冲突/成长机制层"默认关闭但保留高级开关"**：**可逆**是底线——**只"默认关闭/隐藏"不"物理删除"**，以防真有人要硬核 TRPG。
10. **🚫 不做 UI/前端大改**：状态可见层以"文本状态条"实现。

## 第 2 部分 · 产品路线图（三阶段）

> **总原则**：**先能看见问题（阶段一）→ 再把导演器改造成游戏（阶段二）→ 再把承载力变成留存（阶段三）**。三阶段**严格串行**，不可跳跃。
> **周期为估算**【推断】，以单人自研的可支配时间为准。

### 2.0 三阶段总览（依赖关系）

```
阶段一：止血与可观测 ──┐
（先能看见问题）        │  阶段二依赖阶段一的埋点基线
                       ↓
阶段二：形态修正 ───────┐
（把导演器改造成游戏）    │  阶段三依赖阶段二验证过的"形态 + 反馈回路"
                       ↓
阶段三：长线能力
（把承载力变成留存）
```

### 2.1 阶段一：止血与可观测（周期估算：2~3 周）

> **阶段主题**：**先能看见问题，再谈优化。** 修复体验缺陷、补埋点、建基线。**本阶段不碰形态、不做减法**（除零风险项）。

### 2.2 阶段二：形态修正（周期估算：4~6 周）· **本路线图的核心**

> **阶段主题**：**把"导演器"改造成"包裹式体验"。** 方向纠偏、交互变轻、反馈回路、可见化、一键开局、减法。**前提：形态轻量确认（G 组）与方向纠偏并行启动。**

## 第 3 部分 · 个人行为改变方案（"人如何改变"——本报告核心交付之一）

> **原则**：**不要试图提高动机，动机是最不稳定的变量。要降低能力门槛、植入提示。**
> —— 福格行为模型 **B = M × A × P**（行为 = 动机 × 能力 × 提示）

### 3.1 用 B=MAP 拆解："下班后打开它"为什么没发生？

| 要素 | 现状 | 诊断 | 处方 |
|---|---|---|---|
| **动机 M** | 外在动机（造东西）**极强**；内在动机（玩）**弱且被吞噬** | "改代码的即时确定性奖励"持续吞噬"玩游戏的延迟不确定奖励"【user-researcher 1.2】 | **不救动机**（救不动）。承认"想玩"的意愿是波动的，**用结构兜底**。 |
| **能力 A** | **极低**——启动要选卡、要等首字、要读 800~1160 字、要想"我接下来该说什么"、要忍受后台噪音 | 冷启动成本极高，**且恰好卡在"要不要打开"的决策点**；而"改代码"的能力门槛**接近零**（IDE 就在旁边） | **主战场。** 把"玩一次"的启动成本降到接近零（一键继续 + 自动"上回说到"）。 |
| **提示 P** | **缺失**——没有"该玩了"的触发；但"改代码"的触发**无处不在**（bug、灵感、IDE） | 习惯回路：提示（想到一个改进）→ 行为（打开 IDE）→ 奖励（即时确定）。**游玩这条回路根本没建立** | **植入游玩提示**，并**物理隔离开发提示**。 |

**B=MAP 结论**：
> **M 救不动、P 缺失、A 是主战场。**
> 唯一可控的杠杆是 **A（能力/摩擦）** 和 **P（提示）**。→ **把"打开它"的摩擦降到接近零，并把"改代码"的提示物理移出游玩场景。**

**关键洞察【推断】**：**"继续玩"和"开始玩"是两种完全不同的成本。**
- 冷启动成本（高）= 重建上下文 + 选世界观 + 定前提 + 入戏 → 决策点。
- 持续成本（低）= 追加一句反应即可续命 → 所以档能长到 368 回合。
- → **"档很长"衡量的是耐力与沉没投入，不是愉悦。** 破局要打的是**冷启动成本**。

### 3.2 双边责任表（明确区分"产品要改什么"vs"他自己要改什么"）

> **不要把责任全推给产品，也不要把责任全揽在自己身上。这是一场双边谈判。**

| 产品要改（工程侧 · 我负责规划） | 他自己要改（行为侧 · 只有他能做） |
|---|---|
| 后台记账静默化，工具从 49 砍到 ~10 个可见 | **接受更少的控制权**，把旋钮交出去 |
| 伏笔/记忆/奖励自动化 | **停止在游玩中调参**（`set_narrative_style` 372 次 = 调参成瘾，需冷处理） |
| 可见后果叙事化（好感度"演出来"） | **建立"先玩后改"的规则**并执行 |
| 一键继续 + 自动"上回说到"开场 | **分离开发/游玩的时间、设备、账号** |
| 手动风格切换改为自动/隐藏 | **给游玩设结束仪式，允许自己"玩完"** |
| 长档支持（解决 200 上限） | **忍受不完美**，不因一点小瑕疵就重开 |
| StarterKit（94 配置 → 1 次选择） | **做出 M3 的选择**：承认自己更想守护的是"玩"还是"造" |

**核心判断**：产品侧的问题（不可见、手动、高摩擦）是**可以工程解决的**；他自身的问题（逃避、控制欲、身份混淆）**只能靠规则和环境设计来对冲，靠意志力没用**。

### 3.3 三个最关键的行为改变动作（★ 必做）

> 从 user-researcher 的 A–G 方案中，我按"可行性 × 杠杆率"筛出**3 个最关键动作**。这 3 个动作覆盖了"身份冲突、能力门槛、提示缺失"三大问题。

#### ★ 动作 1：把"开发模式"与"游玩模式"在物理上分离（账号 / 设备 / 时间三分离）

> **这是唯一一条能同时解决"控制权冲突、注意力冲突、时间冲突、奖励冲突"的措施。**

| 分离维度 | 具体做法 | 解决什么 |
|---|---|---|
| **不同账号** | 建一个**"玩家账号"**：无权访问管理台/配置/调试工具，看不到 49 工具调用，只能看到叙事输出。**把旋钮从他手里拿走。** | 控制权冲突 |
| **不同设备/入口** | **游玩用手机/网页端**（低摩擦、纯消费）；**开发用 PC 终端**。物理入口不同，大脑自动切换身份。 | 注意力冲突 |
| **不同时间块** | 设**"开发时段"与"游玩时段"**，互不重叠。 | 时间冲突 |

**验证方式**：对照 user-researcher B7 题——如果他的回答是 (b) 煎熬或 (c) 干脆不打开，说明需**进一步降低摩擦**，而非硬扛。

#### ★ 动作 2：降低启动摩擦到接近零（一键继续 + 自动"上回说到"）

- **一键启动** → 自动载入最近存档 → 直接给一段开场钩子。
- **把"从零进入"变成"被世界拉进去"**：从"我要不要开始"变成"我已经在里面了"。
- **产品侧交付 = StarterKit（P1-3）+ 自动开场**；**行为侧交付 = 给自己一条规则："打开产品 = 直接继续，不先看代码"**。
- **为什么是最关键**：冷启动成本是决策点，也是 B=MAP 里唯一可控的 A 杠杆。

#### ★ 动作 3："先玩 20 分钟再改代码"规则 + "待改清单"延迟机制 + 结束仪式

| 子动作 | 具体规则 | 解决什么 |
|---|---|---|
| **先玩后改** | 每次打开产品，**强制先玩满 20 分钟**，期间禁止进入开发环境。 | 把"改代码的即时奖励"往后推，给"游玩的延迟奖励"腾出生长空间 |
| **待改清单** | 想到的改进**写进一个"待改清单"**，不立即执行——把"改"的冲动延迟到游玩结束。 | 打断"想到改进 → 立刻切走"的身份切换 |
| **结束仪式** | 每次结束前**主动写一句"本回结束 + 一句话小结"**，让 session **有意识地结束**，而不是"腻到关掉"。 | 解决"没有自然结束"→ 只能"腻到关掉"→ 重开 |

> **对照验证**：user-researcher B5 题——一档玩到 200 条上限时，感觉是"意犹未尽"还是"终于结束了"？**若是后者，说明当前产品没有"结束仪式"，长档是负担而非奖励。**

### 3.4 成功标准的重构（把 KPI 从"造"换成"玩"）

> **这是本报告对产品负责人最直接的一击。**

| | 旧标准（造物者 KPI） | 新标准（玩家 KPI） |
|---|---|---|
| 核心指标 | 发了多少功能 / 多少 commit / 多少行代码 | **主动打开频率 + 单次愉悦度** |
| 佐证指标 | 44,309 行、49 工具、94 配置 | 最长回合数（权威口径）、状态条外显后的"看见变化"次数 |
| 奖励来源 | "我造了个东西"（即时确定） | "我被故事意外到了"（延迟不确定） |
| 验收方式 | 功能跑通 | **一周内主动打开 ≥ 4 次，且每次自评愉悦度 ≥ 4**（首月目标） |

**具体化**：
- 给自己定一个**"游玩配额"**：首月"**一周主动打开 ≥ 4 次、每次愉悦度 ≥ 4**"；阶段三"**单档 ≥ 1200 回合且愉悦度 ≥ 4**"。
- 记录的**不是 commit 数**，而是"**主动打开的 session 数 + 单次愉悦度**"。
- **护栏**：CDI 不得上升（见第 5 部分）。
- **⚠️ 不要再用"回合数"当成功指标**（user-researcher v4 6.7）：它会被 120/200 统计口径污染，且长档已证可在不愉悦时产生（"都玩到这了，不想半途而废"）。

### 3.5 【核心分叉】如果他的真实动机是"造"而不是"玩"，怎么办？

> **这是本报告必须诚实回答的问题。** user-researcher 的 A3/M1/M3 元问题直指此处：**如果"造东西"本身就能提供心流，那"玩游戏"就是低效的、多余的、甚至令人焦虑的活动。**

**分叉判断工具**（user-researcher A3 题）：
> 如果明天必须二选一，你选哪个？
> **A. 产品从此不能再改一行代码，但你能痛痛快快玩 100 小时**
> **B. 产品随便你改，但你永远只能看别人玩**

**两条不同的路线**（**这不是"好坏"之分，是"诚实"之分**）：

| | **路线 A：承认自己是"造物者"** | **路线 B：承认自己想"玩"** |
|---|---|---|
| **前提** | 选 B（更想造）或 M3 选"更怕产品停止更新" | 选 A（更想玩）或 M3 选"更怕自己再也不玩" |
| **产品定位** | 从"给自己玩的游戏"转为 **"给别人玩的作品"**（工具/平台） | 从"我要造的东西"转为 **"我要消费的娱乐"** |
| **成功标准** | **别人**的留存：第二位玩家能否持续主动打开、单次愉悦度 ≥ 4、分享 StarterKit 能成功开局？ | **自己**的留存：主动打开频率、单次愉悦度（**不是**回合数） |
| **路线图重心** | 重心在**阶段三**（内容供给 + 社区化 + 可分享 StarterKit）；阶段二只做"让产品能被别人玩"的最小集 | 重心在**阶段二**（反馈回路 + 可见化 + 一键开局 + NPC 能动性）；阶段三可弱化 |
| **行为改变** | **不强迫自己玩**。承认"造"是主快乐源，把"玩"当作**产品验收手段**（每版发布前强制玩 20 分钟 = 质量门，而非娱乐）。 | **必须交出控制权**：物理分离 + 先玩后改 + 结束仪式（§3.3 三动作全部执行）。 |
| **风险** | 产品可能永远只有 2 个玩家 → 若 M3 选"更怕停止更新"，此路线会带来"无人看见"的挫败 | 若"造"的冲动太强，会不断破坏"玩"的沉浸 → 需靠规则硬隔离 |
| **最小验证** | 把 StarterKit 分享给第二位玩家，看**他**是否玩得更久 | 自己执行"先玩 20 分钟"1 周，看**自己**是否玩得下去 |

> **我的建议（路径的判断）**【推断】：
> **先走路线 B 的验证（1 周），同时为路线 A 保留接口。**
> 理由：user-researcher 的 E1–E5 与数据都指向"他其实想要的是**被故事意外到**"（他反复选宏大世界观、渴望"值得投入的世界"），而非"只想造"。**如果 1 周后发现自己连 20 分钟都玩不下去，那就是路线 A 的诚实信号**——此时应停止"强迫自己玩"，转向"让别人玩"。
> **最坏的选择是第三条路：既不肯交控制权（无法玩），又不肯服务别人（无法被看见）——那才是真正的困局。**

## 第 4 部分 · 利益相关者沟通（对象 = 他自己）

> **本案特殊性**：产品负责人 = 主要玩家 = 唯一利益相关者。所以"沟通"不是说服别人，而是**让他看见自己三种身份的诉求冲突**。
> 每版 5~8 条要点，**建议分别在不同的心境下读**（开发后读造物者版、想放松时读玩家版、做长期决策时读投资人版）。

### 4.1 【造物者版】——工程师 / 产品负责人关心什么

> 关心：架构健康、技术债、系统优雅、可控性。

1. **你的产品不是"功能太多"，是"近 1/3 的功能不产生玩家可感知的体验"**：221 个功能面中，约 60~70 个（30%）不可见/不可达/断裂/冗余【实测】。这不是能力问题，是**暴露问题**。
2. **65.3% 的调用花在了玩家看不见的记账上**，前 3 个 NPC 记账工具占 **43.9%**。你的引擎在工作，但**工作成果对玩家不可见**——这是"会计系统"的根因【实测】。
3. **CDI ≈ 53/100**（复杂度负债指数），主要债务 = 玩家不可见记账 + 2/3 配置失管。**这是可对外讲的量化口径**【实测】。
4. **14 个工具映射到不存在的技能目录**（含镜像系统 7 个），2 个技能无任何工具指向。你的"收口机制"本身没有收口【实测】。
5. **修复清单很明确**：`<xiaoai_core>` 泄露（25.2%）、编号选项合规（44.9%）、`sync_zone_npcs`（60% 失败，+125 轮次）、`total_latency_ms`（100% 为 0）【实测】。
6. **新的工程纪律**：**新功能上线前 CDI 增量必须 ≤ 0**。把"加功能的冲动"导向"改暴露方式"【data-analyst 建议】。
7. **减法不是否定你的工作，而是把你的深度从"隐性成本"变成"显性卖点"**。SillyTavern 参数比你多，但它把复杂度**外置**了；你要学的是**外置**，不是**删除**。

### 4.2 【玩家版】——那个想放松的人关心什么

> 关心：轻松、沉浸、被意外到、值得投入的时间。

1. **你下班后不想打开它，不是你没毅力——是它要求你"创作级产出 + 消费级阅读"，却只回报"零即时反馈"**。三重负荷叠加，这是**最费神的娱乐组合**【user-researcher 1.5】。
2. **你其实玩得进去**：你和第二位玩家都在本地窗口内玩出了超长档（**单档最高 1062，合计 3931 回合**，不受统计截断）。产品**留得住你**——问题不是"玩不动"，是"**打开它像上班**"【实测】。
3. **它没有给你任何"我做到了"的信号**：好感度涨了你看不到，NPC 因好感度变了态度系统没演出来。**胜任感崩塌是最可推广的病灶**【user-researcher 3.3】。
4. **你可以理直气壮地"少玩一点"**：设定"每周一次、每次 30 分钟"完全合理。产品该为"低频长时"优化，而不是逼你高频【user-researcher D4】。
5. **你反复选宏大世界观，说明你渴望"值得投入的世界"**——但当前产品无法把宏大世界变成"轻松进入"的体验。你缺的不是更多世界观，是**更轻的进入方式**【user-researcher 1.6】。
6. **你想要的是"被故事意外到"**，而不是"指挥一个木偶"。让 NPC 会拒绝、会主动、有秘密——你才可能重新被它打动【user-researcher 3.5】。
7. **给自己三个礼物**：一键继续（不用重建上下文）、开场钩子（被世界拉进去）、结束仪式（允许自己"玩完"而不是"腻到关掉"）。

### 4.3 【投资人版】——如果这是一个要长期投入的项目，什么指标算成功

> 关心：这个项目值不值得持续投入？成功长什么样？

1. **北极星 = 主动打开频率 + 单次愉悦度**（不是功能数、不是 commit 数、**也不是回合数**）。当前均无埋点，需新建。**这是唯一能同时衡量"行为是否发生"与"体验是否值得"的指标。**
2. **护栏 = CDI 不得上升**（当前 53/100）。新功能若提高复杂度负债，一律拒绝——**防止"越做越乱"**【实测】。
3. **首个 30 天成功标准 = 一周主动打开 ≥ 4 次，且期间不新增任何 LLM 工具**（Non-goals 红线）。
4. **90 天成功标准 = 机制层默认关闭 + 包裹式交互上线 + 玩家可见调用占比 0.61/回合 → ≥ 1.5/回合**；CDI ≤ 53【data-analyst 基线】。
5. **180 天成功标准 = 单档 ≥ 1200 回合可持续且愉悦度 ≥ 4；至少 1 套 StarterKit 可分享给第二位玩家并成功开局。**
6. **诚实风险**：单机自研**结构性缺内容飞轮 + 缺运营者**（竞析 W/T）。→ **最务实的定位不是"打败 Character.AI"，而是成为"中文硬核 RP 的自托管跑团"**——用深度做差异化，用预设包降门槛，用状态面板把深度卖出去【竞析】。
7. **最终战略分叉（D3）**：**"私人玩具"还是"服务 100 个陌生人"？** 前者追求"我每天愿意打开"，后者追求"别人愿意打开"。**这个答案决定 30% 的路线图**——请在阶段二开始前回答。

## 一页速览

- **破局优先级（v4）**：**方向纠偏（默认关闭战斗/冲突/成长机制层）> 交互变轻（主导→包裹）> 反馈回路 > 减法**。功能过剩是症状，"方向错配 + 形态错配 + 反馈缺失"才是病灶。
- **一句话定位**：**"一个开箱即玩的中文单人跑团——深度世界状态藏在引擎里，玩家第一分钟就看得见它。"**（竞析方向认同 70%，修正 30%；v4 补正：跑团"规则"重心从战斗/成长移到关系/日常/剧情）
- **Non-goals 红线**：不再新增任何 LLM 工具/配置/skill（新功能 CDI 增量 ≤ 0）。
- **三阶段**：① 止血与可观测 → ② 形态修正（**方向纠偏 + 交互变轻** + 记账隐形 + 可见化 + StarterKit + NPC 能动性 + 减法）→ ③ 长线能力（节奏 + 内容供给 + 长档 + 图鉴）。
- **个人行为改变 3 个最关键动作**：① **物理分离开发/游玩**（账号/设备/时间三分离）② **降低启动摩擦到接近零**（一键继续 + 自动"上回说到"）③ **"先玩 20 分钟再改代码" + 待改清单 + 结束仪式**。
- **成功标准重构**：从"发了多少功能/commit" → **"主动打开频率 + 单次愉悦度"**（**弃用回合数**：会被口径污染，且长档≠愉悦）。
- **核心分叉**：若真实动机是"造"而非"玩" → **路线 A：转为"让别人玩的作品"**；若想"玩" → **路线 B：交出控制权**。最坏是第三条路（既不肯交控制权，又不肯服务别人）。
- **北极星**：**主动打开频率 + 单次愉悦度**（当前无埋点，需新建）｜**辅助**：最长回合数（权威 **1062**）｜**护栏**：CDI 不得上升（当前 53）。
- **30 / 90 / 180 天**：Gate 1（止血 + 形态确认 + 主动打开 ≥ 4 次）→ Gate 2（机制层默认关闭 + 包裹式交互 + 可见化 + StarterKit + CDI ≤ 53）→ Gate 3（单档 ≥ 1200 + 愉悦度 ≥ 4 + 可分享 StarterKit）。
