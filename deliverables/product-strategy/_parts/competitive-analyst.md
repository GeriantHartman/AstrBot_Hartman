# AI 角色扮演（AI RP）竞品对标分析

> 分析人：竞析（Compa）· 竞品分析师
> 分析日期：2026-09-18
> 分析对象：自研 **AstrBot Agentic RPG 插件**（本地部署 / 自带 LLM / 深度 Agent 化）
> 核心问题：**为什么同类产品能让人玩下去，而它做不到？**
> 方法：全部基于 2026-09 实时 WebSearch / WebFetch 检索结果，来源在文末逐条标注。凡未经一手来源证实的均标注「未验证」。

---

## 0. 结论先行（TL;DR）

1. **同类产品能让人玩下去，靠的不是"状态更深"，而是"第一分钟就有反馈 + 第二天有理由回来"。** 我方在两个环节同时失分：上手需要自部署 + 104 项配置（无默认可用路径），留存端**几乎没有任何节奏机制**（无每日内容、无签到、无推送、无社交、无排行榜）。
2. **"状态机 / 工具调用"不是留存的答案，而是留存的成本。** 全行业里只有极少数（我方、aiga_ 部分）真做状态机；头部产品（Character.AI、AI Dungeon、Talkie、猫箱）**几乎都不做传统状态机**——AI Dungeon 官方明确：它**没有 game state、没有工具调用**，一致性靠"摘要 + 向量检索"（来源：help.aidungeon.com）。
3. **复杂度不是原罪，"复杂度裸露"才是。** SillyTavern 的参数比我方只多不少，但它把复杂度**外置**到 6 个可插拔组件 + 社区角色卡/预设市场，本体保持"薄"。我方把复杂度**内置**进 104 个开关，且没有一键开局、没有预设包、没有市场。
4. **最致命的一点：61% 的工具调用是玩家看不见的 NPC 后台记账。** 对比之下，Character.AI 用户投票第一名诉求是"手动编辑角色消息"（46%）、第二名"更好的记忆"（29%）——用户要的是**可见、可干预的反馈**，不是更精密的黑箱。
5. **判断：功能深确实可以是差异化，但我方当前的问题首先是"功能没有被正确暴露"，其次才是"功能过剩"。** 详见第 6 节。

### 2.1 我方的「功能过剩项」（建议收缩 / 隐藏 / 合并）

1. **双流水线并存**：`enable_4_0_contract_pipeline` 与 `enable_5_0_router_supervisor_default` 同时暴露。两套 turn engine 是纯技术负债，用户不该看到这个选择。
2. **NPC 后台记账类工具**：mood / evolution / affinity 自动变更等——占 61% 调用量却对玩家零可见。这是"会计模拟器"的根因。
3. **104 项配置**（本地核对 `_conf_schema.json` 叶子节点 = 104，非 94）：其中 `narrative_review_*` 一个前缀就有 11 项、`router_supervisor_5_*` 6 项、`life_engine_*` 7 项、`character_director/npc_evolution` 十余项。绝大多数用户永远不会碰。
4. **24 个 skill 目录**（`rpg-style-*` 一个系列 8 个）：风格切换应有"预设"概念，而非 24 个独立开关。
5. **调用量≈0 的"内容型功能"**：伏笔（story hook）、记忆、奖励选择——这些**恰恰是留存钩子**，却因为暴露方式错误而无人调用。

### 2.2 我方的「能力缺口」（必须补齐）

1. **一键开局 / 默认可用路径**：全行业标配，我方为零。
2. **可见的状态反馈层**：需要一个"状态栏/关系面板"式的、玩家能看懂的 UI（对标 AI Dungeon 的 Context Viewer、Talkie 的好感度可视化）。
3. **节奏机制**：任何形式的"明天回来"理由（每日事件、连续登录叙事奖励、章节钩子）。
4. **内容市场 / 社区**：至少要有"可分享的预设包 + 角色卡包"机制（对标 SillyTavern 的卡库、猫箱的投稿）。
5. **多模态语音**：2025-2026 中文赛道 TTS 是留存催化剂（Talkie 靠它从"理性使用"转为"情感沉浸"）。
6. **移动端轻量入口**：猫箱/星野证明"上下滑动刷角色"是移动端正确形态。

## 3. 市场趋势（2025-2026）

1. **市场大但分化**：AI 陪伴整体 2025 估值 $37.73B → 2034 $435.90B（CAGR 31.24%，Fortune Business Insights）；但细分"AI 角色扮演聊天"口径不一：QY Research 给 2025 $580M → 2032 $962M（CAGR 7.6%），Bayelsa Watch 给 2026 $625M → 2031 $1.907B。**说明"陪伴"是万亿叙事，"RP"仍是百亿细分**，不要用陪伴大盘给自己定价。
2. **记忆/一致性成为第一竞争维度**：QY Research 明确指出"长对话中保持角色一致性"是行业技术瓶颈与关键差异化。Character.AI 用户投票 29% 要"更好记忆"。→ 一致性是**卖点**，但我方把它做成了**内部机制**而非**玩家可感知的价值**。
3. **Agent 化是少数派，不是主流**：真正做工具调用/状态机的只有我方与 aiga_ 一类。头部全部走"轻状态"路线。**Agent 化是差异化机会，但必须服务于可见体验，否则就是自嗨。**
4. **多模态是留存催化剂**：TTS 情感语音（Talkie）、图像生成（NovelAI/猫箱）、语音通话成为标配方向。
5. **社区化 / UGC 是内容护城河**：BCG 2026 调查显示 40% 玩家比一年前消费更多 UGC；Character.AI 1800 万角色、月新增 900 万；Talkie 83% 自然流量来自 TikTok UGC。→ **单机自研最大的结构性劣势就是没有内容飞轮**。
6. **变现从订阅转向微交易 + 游戏化**：Character.AI 2025 底引入 Charms（赚-花货币），2026.3 免费档 swipe 上限 ~400/天。副作用是用户反感"给聊天行为计费"。
7. **合规与未成年人保护成为硬约束**：Character.AI 2025.11 对 <18 移除开放式聊天，改为结构化 Stories；MiniMax 2025.9 遭迪士尼/环球/华纳版权诉讼。→ 自托管产品在合规上反而有优势（用户自负责）。

## 4. SWOT（我方：一个个人自研的深度 Agent 化 RPG）

| | |
|---|---|
| **S 优势** | ① 唯一真正把"世界状态"作为一等公民的 RP 产品之一（49 工具 / Validator / Director / Memory 多 agent / 双流水线）；② 本地部署、数据自主、无审核、无厂商锁定；③ 角色卡（29 张 canonical）+ 世界观 preset 质量高、有考据（见 SKILL.md 风堇卡）；④ 协议级可控——可任意换 LLM、可深度改造。 |
| **W 劣势** | ① **零留存机制**（无每日/社交/推送/排行）；② 上手成本极高（自部署 + 104 配置，无一键开局）；③ 61% 调用不可见 → 玩家感知不到深度；④ 无 UGC / 无社区 → 无内容飞轮；⑤ 无多模态语音；⑥ **开发者本人已停摆 76 天**（最大风险：项目无运营者）。 |
| **O 机会** | ① "中档空白"：没有产品同时做到"深度状态 + 开箱可用"；② 用户对头部的不满明确且集中——记忆漂移、审核、限流、不可编辑（46% 想编辑消息）——这些正是自托管的强项；③ Agent/工具调用赛道无强敌，先发即差异化；④ 中文 TRPG / 跑团 AI 供给稀薄（aiga_ 等以英文 Discord 为主）。 |
| **T 威胁** | ① 头部以规模碾压内容供给（1800 万角色 vs 29 张卡）；② SillyTavern 生态会自然吸收"状态栏/记忆插件"能力，挤压我方的差异化空间；③ 自研项目停摆风险；④ 单机产品无网络效应，用户获取完全依赖口碑。 |

## 5. 可偷师的 3 个设计（具体到"我该怎么做"）

### 设计一：把 104 个开关变成 1 次"选剧本"——**开局预设包（借鉴 SillyTavern 预设 + 猫箱模板）**
- **竞品依据**：SillyTavern 的"预设"是一整套参数打包、可导入导出，用户从不逐个调参；猫箱提供 300+ 角色/剧情模板 + 问答式引导，"3 分钟熟悉全部操作"。
- **我方怎么做**：
  1. 定义 `StarterKit` 概念 = `世界观 preset + 角色卡 + 风格 skill 组合 + 全部开关的推荐值`，打包成一个 JSON。
  2. 首次启动只问 **1 个问题**："你想玩哪种？① 校园日常 ② 冒险委托 ③ 悬疑推理 ④ 恋爱日常" → 自动套用对应 StarterKit，其余 104 项全部走默认。
  3. 高级开关收进"高级设置"，默认折叠。**默认值必须能玩**——这是当前最大缺失。
- **预期效果**：上手从"自部署 + 配置 104 项"降为"选 1 个剧本"，直接对标头部产品的第一步。

### 设计二：给"看不见的状态"做一个玩家能看见的面板——**可见状态层（借鉴 AI Dungeon Context Viewer + Talkie 好感度可视化）**
- **竞品依据**：AI Dungeon 有 Context Viewer（可视化 token 占用、Memories、Story Summary）；Talkie 把好感度"可视化、进度化"作为核心留存设计；而 Character.AI 用户第一诉求就是"可见 + 可编辑"（46% 想编辑角色消息）。
- **我方怎么做**：
  1. 每回合在正文后附一个**极简状态条**：`地点 / 时间 / 关系（NPC 好感度条） / 当前委托 / 已埋线索数`。
  2. 把 61% 的后台记账**抽样外显**——不是全展示，而是"值得玩家知道的 1-2 条"（如"XX 对你的好感 +1，因为他记得你上次的帮忙"）。
  3. 让"伏笔"变成玩家可见的**悬念卡**："你注意到一个未解之谜……"（把调用量≈0 的 story hook 变成留存钩子）。
- **预期效果**：把"深"从隐性成本变成显性卖点——用户能**看见**自己的世界在生长。

### 设计三：给单机产品装一个"明天回来"的理由——**节奏机制（借鉴 Character.AI 每日任务 + 猫箱签到/节日活动）**
- **竞品依据**：Character.AI 靠 Daily Login + Weekly Quests + Charms 经济驱动回访；猫箱靠签到 + 投稿奖励 + 节日限定角色。
- **我方怎么做**（自托管无服务器，用"叙事化"替代"运营化"）：
  1. **世界内时间**：每天首次登录时，世界推进一小段（NPC 有昨夜发生的事、季节/节日变化）——用叙事制造"错过感"，而非签到打卡。
  2. **章节钩子**：每 N 回合在结尾留一个明确悬念 + "下次继续"（对标 Talkie"几天没登录角色会抱怨"的情感粘性）。
  3. **成就/收藏**：把已解锁的 canonical 角色卡、已完成的委托做成"图鉴"。
- **预期效果**：把"伏笔/记忆/委托"这些调用≈0 的功能，改造成留存引擎。

## 6. 反向洞察：功能深是不是差异化？问题在"功能多"还是"功能没被暴露"？

**我的判断：两者都有，但权重是"暴露 70% / 过剩 30%"。**

**支持"功能深是差异化"的证据：**
- 全行业头部（Character.AI / AI Dungeon / Talkie / 猫箱 / NovelAI）**都不做状态机**，AI Dungeon 官方明确"无 game state、无工具调用"。我方做的世界状态机是**赛道内真实稀缺的能力**。
- 用户对头部的抱怨高度集中在**状态/记忆/一致性/可控性**：Character.AI 用户投票 46% 要"编辑角色消息"、29% 要"更好记忆"；Jenova 引述用户原话"所有模型上下文越长表现越差"。这些**恰好是我方架构的长板**。
- aiga_（TRPG AI 赛道）明确主张"最好的 AI DM 不是写最长段落的工具，而是世界状态、记忆、多人流程"——**说明"状态"确实是被市场认可的价值方向**。

**支持"功能过剩"的证据：**
- 61% 调用玩家不可见 → 深度没有转化为体验。
- 双流水线并存、104 配置、24 skills、调用≈0 的内容型功能 → 典型的"为架构而架构"。
- 开发者停摆 76 天 → 说明**连作者自己都没有被这个产品"留下来"**，这是最诚实的留存信号。

**结论与建议**：
1. **不要砍功能，要砍"功能的暴露方式"。** 把 104 开关 → 1 次选择（设计一），把 49 工具 → 玩家可见的 5 个状态维度（设计二）。
2. **给"内容型功能"（伏笔/记忆/奖励）配上可见的触发时机**——它们调用≈0 不是因为没价值，而是因为 LLM 没有被**激励**去调用、玩家也没有被**告知**它们存在。
3. **保留 5.0 Router Supervisor，隐藏 4.0 Contract Pipeline**——只暴露一条路径。
4. **唯一真正的"过剩"是"没有玩家可见反馈的后台记账"**。这部分应该从"每回合全量执行"改为"按需/抽样执行"。
5. **但要诚实**：即便做完以上，单机自研仍缺"内容飞轮"和"运营者"。所以最务实的定位不是"打败 Character.AI"，而是**成为"中文 TRPG / 硬核 RP 的自托管 SillyTavern+状态机"**——用深度状态做差异化，用开局预设包降低门槛，用状态面板把深度卖出去。

## 附录 B：Talkie/星野「好感度 / 亲密度」可视化深挖（应 user-researcher 请求补充，2026-09-18）

**问题**：Talkie/星野的"好感度进度化"到底怎么可视化的？

**结论：它的可视化核心不是"好感度进度条"，而是"卡牌收藏图鉴 + 关系解锁"，两者构成"可视化成就体系"。**

具体机制（来源：smzdm Talkie/星野解析、星野用户研究报告 2025-12、Talkie 深度测评）：

1. **星念卡牌（核心可视化载体）**：通过抽卡获得 AI 生成的角色卡，带稀有度分级（普通 / 稀有 / 史诗 / 传说）；卡片支持用户间**交易**，稀有卡可值数百元。→ 把抽象的"关系"转化为**可收藏、可展示、可流通的实体资产**。
2. **关系解锁（阶段化剧情）**：互动越多 → 好感度越高 → **解锁更多对话选项和剧情**。→ 把"好感度"转化为**可解锁的内容门**，而非一个数字。
3. **成就 / 徽章**：收集卡片、完成剧情获得成就徽章。→ 第三层可视化。
4. **角色养成**：可"培养"专属角色，看着它"成长"。→ 进度感。
5. 注：对比表中还有一条"送礼提高好感度、解锁剧情"，但其在星野/猫箱/LOFTER 之间的**归属未能唯一确定，标注「未验证」**。

**对方案设计的直接启示**：
- 现成的"可视化范式"= **收藏图鉴 + 阶段解锁 + 徽章**，而不是一根数值条。→ 我方的"好感度"不应只显示为叙事后果或一个整数，而应做成"关系图鉴 / 已解锁内容门 / 已达成成就"三件套。
- 我方的 canonical 角色卡（29 张）+ 委托（commission）+ 伏笔（story hook）**天然就是图鉴与解锁门的内容源**——把它们从"内部状态"改为"玩家收藏面板"，是零新增内容、纯暴露层的改造。

**额外重要背书（对全团队）**：星野**自己的用户研究**（105 份问卷，SUS 67.8 分，低于行业平均）结论是——**"删除或隐藏非必要功能，提供『功能自定义』开关"**；其"功能操作繁琐"仅 2.11/5 分，56% 用户遇到交互逻辑混乱。这为我方"隐藏 104 个开关、做一键开局"提供了**竞品自家用户研究的背书**，定性可从"创新"降级为"补课"。

**另一条对"状态机长板"的利好**：星野用户痛点前二为记忆差（63.8%）、剧情连贯性差（65.7%），83.8% 用户要求提升剧情连贯、80.95% 要求强化记忆。→ **记忆/一致性是全行业未解痛点，正是我方状态机架构的价值所在**——但必须先被玩家感知。
