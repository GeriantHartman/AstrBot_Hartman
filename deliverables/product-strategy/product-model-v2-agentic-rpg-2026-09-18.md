## 📌 TL;DR

- **负责人的 Q1/Q4 纠正的不是数字，是我的分析框架**：`time_slice` 是**独立的游戏内叙事时间**，不取决于现实时间。**AI RP 中没有任何字段取实际值。** → 我原来的「四层时钟 → 收敛为单一时间源」是一个**数据库一致性框架**，用错了镜头。正确的镜头是**叙事自洽性**。
- **★ 本轮最重要的发现**：负责人说的「世界事件」在产品里**有表、有 schema、有 267 条数据，但零读取**。`timeline_events` 是一张**只写不读的死表**，且写入类型被硬编码，实际只是 `episode_memories` 的镜像副本。
- **与此同时，「原不可变世界观」（`world_canon`）是活的**——144 条，其中 **81 条是玩家自己声明的**（56%），并被注入 LLM（措辞："不可在叙事中推翻"）。
- **→ 产品目前的形态是：世界观是「可声明的」，但世界的变化是「不可记录的」。** 玩家只能改变世界的**初始条件**，不能改变世界的**历史**。
- **这一个概念缺口解释了四个症状**：C6 关系扁平 / 19% 的"叙事跳顶" / Q5 的跨 session 两难 / B4 的时间不自洽。
- **Q3 的答案让我撤回 P0-7**：负责人说"没遇到过誓约门槛，而且看起来其他玩家也不喜欢这种门槛" → **门槛机制不该做**。

## 1. 负责人的五条纠正（原文保留）

> **Q1.** `time_slice` 你理解错误。这是一个独立的游戏内时间，它不取决于现实时间。也就是说，**它是一个叙事字段，而不是实际字段。AI RP 中没有任字段取值实际。**
>
> **Q2.** 世界事件指的是**该 session 相对于原不可变世界观，产生了哪些大变化，是属于这个 session 独有的**，可能是玩家行为引发，或者玩家要求。这属于**自由探索产生的事件**。
>
> **Q3.** 没遇到过誓约门槛，而且**看起来其他玩家也不喜欢这种门槛**。
>
> **Q4.** 同 1，这是游戏内叙事字段。用于让 LLM 理解当前场景处于什么时间段。也是用来**控制不合理的时间变化**，例如下楼去便利店，时间段切换，从逻辑上看，**花了半天时间去楼下便利店买牛奶，这不合理**。
>
> **Q5.** 暂时没想好怎么处理。但**直接开局在世界事件中进行设定并非不可接受。而且玩家基本上都这么干。** 如果强制执行跨 session 继承关系，又会不满足玩家开新 session 可能是想要新世界、新的新意的感觉。可能不想那么快遇到那个角色。可能想要新的发展。

## 2. Q1/Q4 的框架纠正：从「数据库一致性」到「叙事自洽性」

### 2.1 我原来错在哪

| | 我的框架（错） | 负责人的框架（对） |
|---|---|---|
| **本体** | `time_slice` 是**状态字段**，多个表各存一份 → 必须收敛为一个权威源 | `time_slice` 是**叙事字段**，用于让 LLM 理解"当前场景处于什么时间段" |
| **判据** | 表与表之间是否相等（一致性） | **叙事是否自洽、时间推进是否合理** |
| **缺陷定义** | "三层时钟不同步" | "LLM 收到的输入本身矛盾" / "时间跳跃不合理" |
| **修法方向** | 建立单一时间源 | 保证**同一回合内呈现给 LLM 的叙事信息不自相矛盾** |

### 2.2 纠正后，哪些结论仍然成立

**✅ 仍然成立，但换了表述**：

| 原结论 | 纠正后的表述 |
|---|---|
| "L4 vs L1 一致率 56.5%" | **43.5% 的情况下，玩家正在阅读的 zone 描述，其生成时间与该场景的当前时间是不同的时间段**。→ 这是一个**叙事自洽性指标**，不是 DB 一致性指标 |
| "`get_time_info()` 把冻结值注入 LLM 上下文（13 调用点 / 5 注入点）" | **叙事者被告知一个不属于当前场景的时间**。无论用什么本体论，**给 LLM 的输入自相矛盾**都是缺陷 |
| "`move_to_zone` 先物化后推进" | 玩家移动后，**新到达地点的描述是用"出发时"的时间生成的** → 叙事上是"你到了，但房间还是你出发时的样子" |

**❌ 需要撤回的表述**：
- 「四层时钟 / 建立单一时间源 / 消除三层时钟」——**这是代码一致性框架，不是产品框架**。
- 正确的产品表述应是：**"同一回合内，呈现给 LLM 的时间信息必须指向同一叙事时刻"**。至于底下有几张表、怎么存，是工程实现细节，**不是产品问题**。

### 2.3 Q4 揭示了更深的一层：时间推进的判据错了

负责人说这个字段的用途之一是「**控制不合理的时间变化**」，例子是：

> 「下楼去便利店，时间段切换，从逻辑上看，**花了半天时间去楼下便利店买牛奶，这不合理**」

**这暴露了一个设计原则问题**：

```
现状：time_cost 由 LLM 传一个整数（time_cost: int = 1）
      ↓
      代码无法判断这个数字是否被叙事支持
      ↓
      于是用 "位置是否变化" 当粗粒度代理（location_changed）
      ↓
      结果两个方向都错：
        · 下楼买牛奶（位置变了）→ 推进 1 个时间片（不该推）
        · 在原地等一整夜（位置没变）→ 完全不推进（该推）
```

**产品原则应是**：**时间推进的判据是"叙事意义"，不是"位置变化"。**

而这恰好呼应负责人在 C7 说的设计原则——「**我的设计都是 LLM 来调用工具，不应该人来调用**」：

> **叙事时间由叙事驱动**：只有 LLM 知道"下楼买牛奶"和"在公寓里等天亮"在叙事上分别意味着什么。代码的职责是**校验合理性**（给一个合理的上界），不是**用位置变化代替叙事判断**。

## 3. ★★★ 核心发现：「世界事件」是一个有容器没有内容的机制

负责人 Q2 给出的心智模型非常清晰：

> **原不可变世界观（不变） + 该 session 独有的变化（世界事件，可变）**

我按这个模型去核查数据库，结果是——**这个模型的一半是活的，另一半是空的。**

### 3.1 数据核查（18 个 ic>0 会话，脚本 `_r2_scripts/lead_world_events.py`）

| 承载概念的表 | 总行数 | 有数据的会话 | 写入 | **读取** | 状态 |
|---|---:|---:|---|---|---|
| **`world_canon`**（原不可变世界观 + 玩家声明） | **144** | 10/18 | ✅ | ✅ **3 处注入 LLM** | ✅ **活的** |
| **`timeline_events`**（世界事件日志） | **267** | 15/18 | ⚠️ 单一类型 | ❌ **零读取** | ❌ **只写不读的死表** |
| `semantic_chronicles`（会话编年史） | 10 | 10/18 | ✅ | ✅ 注入 | ✅ 活的 |
| `npc_evolution_log`（NPC 演化） | 213 | 11/18 | ✅ | — | ✅ 活跃 |
| `episode_memories`（记忆片段） | 295 | 16/18 | ✅ | ✅ | ✅ 活跃 |
| `global_flags`（会话标记） | **6** | 5/18 | ❌ | ✅ 有读取 | ❌ **几乎未使用** |
| **`story_hooks`**（伏笔/悬念） | **1** | **1/18** | ❌ | ✅ 有读取 | ❌ **几乎未使用** |

### 3.2 `timeline_events` 为什么不是"世界事件日志"

**三条证据**：

**① 写入类型被硬编码**（`core/state_machine.py:2704` 的 INSERT）：
```sql
INSERT OR REPLACE INTO timeline_events
    (event_id, ..., event_type, summary, importance, created_at)
VALUES (?, ..., 'episode_summary', ?, 50, ?)
                ^^^^^^^^^^^^^^^^^^ 字面量，不是参数
```
且 `source_type` 同为字面量 `'episode'`。
→ **schema 预留了 `event_type` 的多样性（默认值就是 `episode_summary`），但代码结构上永远只能写这一种。**

**② 实际数据 100% 单类型**：
```
event_type  : {'episode_summary': 267}   ← 100%
source_type : {'episode': 267}           ← 100%
```

**③ 它是 `episode_memories` 的镜像，不是独立日志**：
- **16/18 个会话中，`timeline_events` 计数 == `episode_memories` 计数**（1062 回合档：85/85；512：27/27；498：32/32；408：37/37）
- `event_id` 的构造是 `f"episode:{mem.summary_id}"` → **一对一映射**

**④ 零读取**：`get_timeline_events`（`state_machine.py:2789`）**全库没有任何调用点**。

> **结论：`timeline_events` 是一张"以为在记录世界事件、实际只是复制记忆摘要、而且从来没人读过"的表。**
> **它有 267 条数据，但这些数据从未到达过 LLM。**

### 3.3 对照组：`world_canon` 是活的，而且玩家已经在用

**`world_canon` 的 144 条数据里，`source` 分布**：
```
player_declared : 81  (56.3%)   ← 玩家自己声明的
gm_ruled        : 63  (43.8%)   ← 系统判定的
```

**玩家的 `topic` 样本**：
```
character:墨（前世开拓者）
character:爱莉希雅
character:墨的睡眠记录
character:昔涟
character:丽塔·洛丝薇瑟
world:era
world:current_timeline
player:identity
event:比赛公平性
```

**注入路径**（3 处）：
- `handlers/narrative_package.py:1585` → `world_canon_block`，注入措辞：
  > 「## 此世界既定设定 (world_canon) / 若与你记忆里的原作设定冲突，以 canon 为准。**不可在叙事中推翻。**」
- `handlers/npc_tools.py:2158`
- `handlers/router_context.py:357`

### 3.4 ★ 这两个事实合起来意味着什么

> **玩家要的机制里，「世界观」那一半是活的，「世界事件」那一半是空的。**
>
> - 玩家**可以声明世界是什么样**（`world_canon`，81 条，被注入，被尊重）
> - 玩家**无法记录世界发生了什么**（`timeline_events` 只写不读，且只镜像记忆）

**→ 玩家只能改变世界的「初始条件」，不能改变世界的「历史」。**

## 4. 一个概念缺口，四个症状

这个缺口把第二轮里几个看似无关的发现串成了一条因果链：

| # | 症状 | 因果链 |
|---|------|--------|
| **1** | **C6 关系扁平**（好感度是单向棘轮，98% 正 delta） | 关系变化**没有事件载体** → 只能记成 `npc_player_affinity.value` 一个整数 → 整数无法表达"发生了什么" → 中间态在叙事上不可见 |
| **2** | **19% 的"叙事跳顶"**（`reason` 原文："前世挚爱回归，好感修正至满值" / "跨越三千三百万次轮回的羁绊"） | 玩家想让关系**从一个设定好的状态开始**，但"世界事件"机制是空的 → **只能退回到唯一可用的机制：写 `world_canon`**（"墨（前世开拓者）"正是 81 条玩家声明之一）→ 然后用叙事把它翻译成好感度 |
| **3** | **Q5 的跨 session 两难** | 没有**独立的世界事件层** → 无法"选择性携带"（带关系但不带剧情 / 带世界但不带角色）→ 只能**全带**（强制继承，破坏新意）或**全不带**（新世界，切断连续性） |
| **4** | **B4 时间不自洽** | 叙事时间**没有事件锚点** → 时间只是一个字段值，不是"在某时刻发生了什么" → 一旦字段之间不同步，就没有任何东西能判断哪个是对的 |

> **一句话**：**玩家在用「声明正典」这一个可用机制，去勉强实现本该由「世界事件」承载的一切。**

### 4.1 与竞品结论的呼应

- **Hades 心锁**（竞析）：关系阶段由**世界事件**门控 —— 这正是缺口所在。
- **Character.AI Facts 可迁移**（竞析）：Facts 本质是**可携带的"世界事件摘要"** —— 这也正是缺口所在。
- **"好的连续性往往是安静的"**（Nomi）：连续性不需要喊出来，只需要**被记录**。

**三个独立来源都指向同一个机制。** 这不是巧合——**它是这个品类的核心机制**。

## 5. Q3：撤回 P0-7（誓约门槛）

**负责人回答**：「没遇到过誓约门槛，而且看起来其他玩家也不喜欢这种门槛。」

**裁定：P0-7 撤回。** 理由不只是"玩家不喜欢"，而是它**与 Q2 的世界观相冲突**：

| | 门槛机制（P0-7，撤回） | 世界事件机制（Q2） |
|---|---|---|
| 关系如何推进 | 数值累积到阈值 + 里程碑计数 ≥ N | **发生了某件事** |
| 玩家感受 | "我在刷指标" | "我们之间发生了一件事" |
| 对治 C6 的方式 | 让中间态更难到达（治标） | 让每个阶段**有事件可指**（治本） |

**→ 正确的方向不是"加门槛"，而是"给关系一个事件载体"。** 这与第 3 节的发现完全一致。

**同时撤回**：P0-5 的「`value≥80` 且里程碑数 ≥ N 才可进入誓约」中的**门槛部分**。里程碑本身（记录"发生了什么"）保留——**但它的作用是"记录"，不是"门控"**。

## 6. Q5：不强制继承，而是「可携带」

**负责人回答**：「直接开局在世界事件中进行设定并非不可接受。而且玩家基本上都这么干。如果强制执行跨 session 继承关系，又会不满足玩家开新 session 可能是想要新世界、新的新意的感觉。可能不想那么快遇到那个角色。可能想要新的发展。」

**裁定：撤回 P1-6 的"跨 session 关系延续"作为默认行为。**

**新的设计原则**：

> **继承应是「可携带的」，不是「自动的」。**

| 维度 | 现状 | 应有 |
|---|---|---|
| 世界观 | 玩家已能声明（`world_canon`，81 条） | 保留 |
| 世界事件 | **无载体** | 新增：session 独有的事件层 |
| 关系 | 只能靠叙事跳顶 | 由**事件**表达，而非数值 |
| 跨 session | 全带或全不带 | **玩家选择携带什么**（带世界？带事件？带关系？带角色？分开选） |

**关键**：Q5 的两难（继承 vs 新意）**本身就是"没有独立世界事件层"的产物**。一旦世界事件可以独立携带，玩家就能"带这个世界的历史，但不带那个角色"——**两难消解**。

**同时确认**：「**开局在世界事件中设定**」是**合法的、且是主流用法**——所以产品应**支持它**，而不是把它当作"玩家在绕过攻略"。这与第 2 节的数据吻合（81 条玩家声明）。

## 7. 修订后的产品模型

```
┌─────────────────────────────────────────────────────────┐
│  原不可变世界观（canon）                                  │
│  ✅ 已实现：world_canon（144 条，56% 玩家声明）            │
│  ✅ 已注入 LLM（"不可在叙事中推翻"）                       │
│  性质：不变 · 可声明 · 是"世界的设定"                      │
└─────────────────────────────────────────────────────────┘
                          ↓ 玩家在其中行动
┌─────────────────────────────────────────────────────────┐
│  ★ 世界事件（session 独有变化）  ← 【缺口在这里】          │
│  ⚠️ 名义载体：timeline_events（267 条，但零读取 + 单类型）  │
│  ❌ 实际缺失：没有任何东西在记录"世界变了什么"              │
│  性质：可变 · 属于本 session · 由玩家行为或要求引发         │
│  应有作用：① 关系的表达载体 ② 跨 session 的可携带单元       │
│           ③ 叙事时间的锚点 ④ 新鲜感的来源                  │
└─────────────────────────────────────────────────────────┘
                          ↓ 由事件驱动
┌─────────────────────────────────────────────────────────┐
│  关系 / 角色状态 / 叙事时间                               │
│  ⚠️ 关系：只有数值（npc_player_affinity），无事件            │
│  ⚠️ 叙事时间：存在但语义分散，给 LLM 的是冻结值             │
│  ✅ 记忆：episode_memories / semantic_chronicles 是活的     │
└─────────────────────────────────────────────────────────┘
```

**一句话**：**产品的世界观层已经建好了，但"世界会变"这件事没有被记录。而"世界会变"正是 RPG 的全部意义。**

### 8.5 ★ 与「世界事件」的耦合

## 9. Q6–Q10 的吸收

### 9.1 Q6：世界事件的**精确粒度**——只有「改变世界状态」才算

**负责人原话**：
> 「只有改变了世界状态才算，下楼买牛奶不算。跨越三千万次轮回是**背景设定**。所以这两个例子都不是世界状态。」

**→ 这把我原来的假设收窄了。三个层次必须严格区分：**

| 层次 | 例子 | 是否世界事件 | 性质 |
|---|---|:---:|---|
| **背景设定**（canon） | 「跨越三千万次轮回的羁绊」「前世挚爱」 | ❌ | 不变 · 可声明 · **不可推翻** |
| **剧情节拍**（narrative beat） | 「下楼买牛奶」「和她说了一会儿话」 | ❌ | 一次性 · 不改变世界 |
| **世界状态变化**（world event） | 某 NPC 死亡/离开 · 地点被毁/建立 · 势力关系改变 · 秘密被揭露 | ✅ | **不可逆** · session 独有 · **由玩家行为引发** |

> **关键**：世界事件的门槛**比我想的高得多**——不是"发生了什么"，而是"**世界因此不一样了**"。
> **→ 这也修正了我上一轮的表述**：19% 的"叙事跳顶"（"前世挚爱回归"）**不是世界事件**，它是**背景设定**（canon）。见 §9.3。

### 9.2 Q7/Q9：由 **LLM** 识别与判定

| 项 | 答案 |
|---|---|
| **Q7 谁来写世界事件** | **LLM 识别并写** |
| **Q9 时间推进的合理性上界** | **LLM** |

→ **两条统一到同一个原则**：**叙事层的事由叙事层（LLM）判断，代码只提供机制与边界。**
→ 这与负责人 C7「我的设计都是 LLM 来调用工具」完全一致，也是本项目「代码只处理确定性事件」规范的直接推论。

### 9.3 ★★ Q8：世界状态**永不晋升为正典**——这暴露了一个层次混淆

**负责人原话**：
> 「不晋升。世界状态只是 session 级别行为，不上升正典。因为**其他人可能也在玩同一个世界观，不同 session 不应影响**。」

**→ 这是一条硬约束：`canon` 是共享的、`world state` 是 session 独有的，二者不可跨越。**

**但现状违反它——而且违反的方式很具体**：

```
world_canon 的 144 条里，81 条是 player_declared（56%）
样本：character:墨（前世开拓者） · character:爱莉希雅与墨 · player:identity
注入措辞：「此世界既定设定」… 「不可在叙事中推翻」
```

**"墨（前世开拓者）"、"爱莉希雅与墨"——这些是【这一局】的关系设定，不是【这个世界】的设定。**
但产品把它们写进了 `world_canon`，并赋予「**不可推翻**」的语义。

> **★ 结论：产品缺少一个「session 级的、可推翻的设定层」，于是玩家只能把 session 级设定塞进 canon 层。**
>
> | 层 | 应有语义 | 现状 |
> |---|---|---|
> | **世界观**（canon） | 共享 · 不变 · 不可推翻 | ✅ 有（但**混入了 session 级内容**） |
> | **session 设定** | 本局独有 · **可推翻** · 不晋升 | ❌ **缺失** |
> | **世界状态变化** | 本局独有 · LLM 识别 · 不可逆 | ❌ **缺失**（`timeline_events` 只写不读） |

**这解释了那 81 条 `player_declared` 的存在**：玩家想设定"这一局我和她的关系起点"，产品没有 session 级的槽位，于是写进了 canon。

**→ 而这也回答了 Q5 的两难**：一旦有独立的 session 设定层 + 世界状态层，「带这个世界的历史但不带那个角色」就自然成立，**继承 vs 新意不再是二选一**。

### 9.4 Q10：携带粒度**四者可分开选**

| 可携带单元 | 能否独立选择 |
|---|:---:|
| 世界观（canon） | ✅ |
| 世界状态（events） | ✅ |
| 关系 | ✅ |
| 角色 | ✅ |

→ **P1-6 的修订方案（"可携带而非自动"）被确认**，且粒度是**四轴独立**。

## 11. ★ 撤回 §9.3 的「层次混淆」——那是我对架构的误读

### 11.1 负责人澄清

> 「你 canon 目前是 **session 隔离的**，或者我们的讨论概念不一致。**世界观我指的是 preset**，也就是基础属于哪个世界。开启 session 后产生的 canon 应该**只归属于该 session**。在新的 session 选择同一个 preset，也**不会注入这些 canon**。」

### 11.2 代码确认：负责人是对的

```
preset（世界观）= data/plugins/astrbot_plugin_agentic_rpg/presets/*.json
                  （new-elysium.json / genshin.json / star-rail.json …）—— 共享文件
        ↑ 被引用
game_sessions.world_preset TEXT DEFAULT 'default'   —— 每个 session 记录自己属于哪个世界
        ↓
session DB（每个 session 一个独立 .db 文件）
   └─ world_canon 表 —— 只存在于该 session 的库里 → 【本来就是 session 隔离的】
```

**→ 我在 §9.3 说的「产品缺少 session 级设定层、玩家只能塞进 canon 层」是错的。**
`world_canon` **就是** session 级设定层，而且隔离性是正确的。那 81 条 `player_declared` 是**正确用法**，不是"层次混淆"。

**我错在哪**：我看到表名叫 `world_canon`、注入措辞是「此世界既定设定」，就推断它是"世界级共享层"，然后发现里面装着 session 级内容，于是判定为"混淆"。
**实际上**：`world_canon` 的 `world` 指"这个游戏世界"，但它存在 session 库里 → 是 session 级的。**名字误导了我，不是架构有问题。**

**（保留一条次要观察）**：表名 `world_canon` + 注入措辞「此世界既定设定 / 不可在叙事中推翻」，确实容易让**开发者或 LLM** 误判它的作用域。这是**命名问题**，不是架构问题。

## 12. ★ 数据验证：我的「封顶靠声明」假设只对 24%

**假设**：那 37 条 =100 的关系是**声明出来的**（初始状态），不是**累积出来的**（过程状态）。

**实测**（`_r2_scripts/lead_declared_vs_earned.py`，18 个 ic>0 会话 / 125 条关系）：

| 指标 | 结果 |
|---|---|
| 关系总数 | **125** |
| `value == 100` | **37（29.6%）** |
| history 含"声明语言"（前世/宿命/羁绊/契约/∞/设定…） | **11/125 = 8.8%** |
| **其中落在 `value==100` 的** | **9/37 = 24.3%** |
| 声明组 stage 分布 | **誓约 10 / 敌对 1**（91% 落在誓约） |
| 累积组 stage 分布 | 陌生 39 / 誓约 35 / 友善 20 / 信赖 9 / 亲密 5 / 厌恶 5 / 敌对 1 |
| history 长度中位 | **声明组 2** vs **累积组 4** |

**会话级对照（decl = 玩家声明的 canon 条数，aff@100 = 封顶关系数）**：

| session | ic | decl | aff@100 |
|---|---:|---:|---:|
| `FriendMessage_2438094710` | **1062** | **0** | **5** |
| `FriendMessage_942361330` | 512 | 14 | 5 |
| `GroupMessage_1090658701` | 498 | 19 | 8 |
| `GroupMessage_230394566` | 408 | 9 | 5 |

**结论：**
1. **假设部分成立（24.3%）**——近四分之一的封顶确实是声明出来的，且声明组 91% 落在誓约、history 更短（2 vs 4）。这印证了"玩家会用声明设定关系起点"。
2. **但不是主因**——**约 76% 的封顶是累积出来的**。
3. **会话级没有干净相关性**——回合最多的档（1062）声明数为 **0** 却有 5 条封顶；声明最多的档（19 条）有 8 条封顶。

**→ 修正后的 C6 诊断（比"声明 vs 累积"更准）**：

> **两条路径（声明 / 累积）的终点是同一个（100 / 誓约）。**
> - **声明路径**：一步到位（24%）
> - **累积路径**：约 14 次 +7 的 bump 走完（76%）
> - **但终点统一**，且**到达后不再变化**（没有过程状态去演化它）
>
> **→ "二极管"的成因不是"只有两极有区别"，而是"所有关系都收敛到同一极"。**
