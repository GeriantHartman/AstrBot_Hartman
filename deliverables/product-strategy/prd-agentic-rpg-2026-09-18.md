## 📌 TL;DR（执行摘要）

- **核心目标**：把产品从「**让玩家一起创造世界**」改为「**让玩家消费一个写好的世界，然后即兴演出**」——这是负责人亲述（开放问题 2「**我想消费一个写好的世界**」）与瑞思的用户裁决（「**消费布景，即兴演出**」）的合流点。
- **关键决策**：**当前产品把两件事都做反了**——世界观层本该由产品提供，却要求玩家生成；行为层本该由玩家自由，却被编号选项约束。**这不是"功能太多"，是两条产品线的叠加**（49 个工具中仅 ~16 个服务负责人真正要的循环）。
- **关键决策**：**P0 收敛为 4 项确定性缺陷**（全部可代码修、全部已定位到行号），而非 8 项。
- **下一步**：先修 4 项 P0（其中 3 项是单点修复），再建"关系=设定"机制（反二极管），最后降复杂度。
- **一句话诊断**：**"不愿游玩"不是因为产品复杂，是因为每回合都要他付出创造劳动，而他想要的是消费。**

## 3. 用户研究洞察（瑞思）

### 3.1 核心裁决：**「消费布景，即兴演出」**（consume the set, improvise the performance）

| 层次 | 玩家的要求 | 当前产品 | 判定 |
|------|-----------|---------|------|
| **世界观层** | **产品提供**（"我想消费一个写好的世界"） | 让**他**生成（要他想地点、驱动剧情） | ❌ **做反** |
| **行为层** | **灵感脚手架**（有选项，可接受可不接受） | ⚠️ 见 §3.3（**本条已被负责人推翻并重新裁定**） | — |
| **关系层** | **已成立的设定** | 要求逐点攻略 | ❌ **做反** |

> ⚠️ **§3.1 的"行为层"一行与 §3.3 整节均已被负责人于第三轮推翻。** 结论见
> `product-model-v2-agentic-rpg-2026-09-18.md` §8：**编号选项是正确的机制**，
> 它降低"想接下来说什么"的构思成本并提供意外感；**低合规率是缺陷，不是玩家的偏好**。

### 3.2 动机模型：**「起念于关系，续命于建造，熄火于新鲜感耗尽」**

- **起念**：动机来自**关系**（想见那个角色）→ 这解释了 A2 自评动机 10
- **续命**：靠**建造感**（看到世界因自己而变）→ 这是"建造者悖论"的来源
- **熄火**：**新鲜感耗尽**（E3「想要新鲜感」/ 开放问题 1「没有新鲜感」）→ 这解释了 A6「不想玩」

### 3.3 ★ 判定反转：编号选项的"合规率"优化方向**是反的**

第一轮曾把"LLM 未输出编号选项"判为缺陷。**瑞思用数据推翻了这个判定**：

- 编号选项**合规率 44.9%**（即 **55.1% 的回合 LLM 没输出选项**）
- 负责人 B2 把"想接下来说什么"打 **4 分**（最痛），把"等首字/读输出"打 **1 分**
- → **他要的是纯叙事，不是菜单**。LLM"不合规"的行为**恰好是玩家想要的**

**结论：优化方向应改为"移除强制菜单契约"（R11），而非"提高合规率"。** 这是本轮最有价值的判定反转。

## 4. 竞品对比（竞析，23 条来源）

### 4.1 「预写世界 + 关系养成」的赛道定位

**该品类存在，但不在 AI 原生赛道**：Hidden Door / SillyTavern（预写世界）vs Replika / Character.AI（AI 原生）。**产品处在两者之间的空白区**——这既是机会也是风险（无现成范式可抄）。

### 4.2 ★ 二极管是**品类通病**，真正"不二极管"的全在单机

| 产品 | 关系机制 | 是否二极管 |
|------|---------|-----------|
| Replika | 自认 Level 30/50 **只是软里程碑** | ⚠️ 二极管 |
| Character.AI | 无关系数值 | ⚠️ 扁平 |
| **Persona / Fire Emblem** | 关系由**剧情事件**推进 | ✅ 不二极管 |
| **Hades（心锁）** | **关系阶段由世界事件门控** | ✅ **天然反反复攻略** |
| **Baldur's Gate 3** | 关系由**选择**推进 | ✅ 不二极管 |

### 4.3 三个可直接偷师的机制

| # | 偷师对象 | 机制 | 对治 |
|---|---------|------|------|
| **A** | **Hades 心锁** | 关系阶段由**世界事件**门控（不是刷数值），且**天然反反复攻略** | C6 二极管 + "不喜欢反复攻略" |
| **B** | **Character.AI Facts** | 关系/设定是**可迁移的记忆卡**，可一键复制到新 chat | **直接对治 C6 的 reset 问题** |
| **C** | **DreamGen Steering** | **意外度旋钮** + Swipe 重掷 + Continue | E3「想要新鲜感/意外感」 |

**关键洞察（Nomi）**：「**好的连续性往往是安静的**」——记忆与风格应合并为**一个机制**，而不是两个独立功能。

### 5.4 ★ 世界时钟：**LLM 自己都不知道现在是几点**

**四层时间源**（析客裁决 + 主理人验证）：

| 层 | 字段 | 角色 | 状态 |
|---|---|---|---|
| **L1** | `scenes.time_slice` | ✅ **权威** | 由 `advance_scene_time` 写 |
| **L2** | `game_sessions.max_time_slice` | ✅ 世界高水位（单调） | 由 `_sync_world_clock` 写 |
| **L3** | `game_sessions.current_time_slice` | ❌ **僵尸字段** | **写入已停，读取未停** |
| **L4** | `zones.time_slice` | ❌ zone 渲染戳（**派生**） | 由 `update_zone_volatile` 写 |

**三层全量普查（23 个 session×player，主理人与数析独立复现一致）**：

```
L4(zones) vs L1(scenes) = 13/23 = 56.5%   ← ★ 唯一有效的"时间不一致"基线
L4(zones) vs L3(遗留)   =  9/23 = 39.1%   ← 旧口径，混入 L1/L3 分叉噪声（L1≠L3 高达 73.9%），已弃用
scene.local_id == player.current_local_id = 23/23 = 100%   ← 入口对得上，时间对不上
```

**★★ 决定性闭环**：

```python
# core/state_machine.py:2631
async def get_time_info(self, session_id: str) -> dict:
    """Get full time info for LLM context injection."""     # ← docstring 自证用途
    return {
        "time_slice": gs.get("current_time_slice", ""),     # ← ★ 裸读 L3 僵尸字段
        ...
    }
```

**13 个调用点，其中 5 个直接注入 LLM 上下文**：
`prompt/assembler.py:321` / `:668` / `:853`、`handlers/router_context.py:246`、`handlers/narrative_package.py:1354`

**同一次生成里，LLM 收到三份互不相同的时间**：
1. **L3**（`get_time_info` → prompt）——**冻结在某个历史时刻**
2. **L1**（scene 权威）——真实当前时间
3. **L4**（zone 描述的时间词）——**移动前**的时间（因 `move_to_zone` 先物化后推进）

**→ 负责人 B4「时间段切换是否合理」不是他的错觉，是 LLM 面对的输入本身就是矛盾的。**
