# 剧作家插件（art）设计方案

状态：设计已定，尚未开始写代码。
定位：`astrbot_plugin_art`，与 `astrbot_plugin_agentic_RPG` 并存的独立插件、独立版本。

---

## 1. 这个插件要解决什么

旧 RPG 插件跑了一年，暴露三个问题：

1. **玩家变成了生产者。** 剧情往哪走、下一步做什么，全靠玩家构思。系统里没有任何部件负责「故事接下来发生什么」。
2. **功能越加越多，大部分没用。** 数值、光锥、装备、检定、委托后期基本被忽略。
3. **角色缺神韵。** 卡写得像规格书（防止写错），而不是「这个人怎么想事情」。

art 只做一件事：**让玩家当消费者。**

验收基准（跑分已有基线，见第 9 节）：

```
raw（只给 YAML 卡，不走插件） = 角色对 + 写作平庸
art（本插件）                 = 角色对 + 写作有指导 + 故事自己会走
```

**神韵不许退步**（跑分管），**写作要变好**（人主观评）。

## 2. 砍掉什么

公平性机制整套退场——单人游玩，没有对手，不需要防作弊。

| 旧功能 | art 的去处 |
|---|---|
| D20 检定、属性、光锥、装备、技能、mirror 战斗 | 四层变数（第 6 节） |
| 好感度数值、NPC 进化触发 | 关系账本（第 7 节） |
| 委托、life engine、节日/天气系统 | 编剧钩子 + 日历（第 5 节） |
| 经验、等级、交易、露营、背包、状态栏 | 删。礼物作为回忆进账本 |
| 区域(area) / 地点(zone) 两层地理 | 合成一层「场景」 |
| Director（逐 NPC 生成内心 JSON） | 删。推理模型自己会揣摩，中间转述是神韵流失的来源 |
| 4.0 contract / 5.0 brief / Validator / 审计全套 | 删。只留最简请求-回复日志 |
| 9 种 rpg-style-* | 收成一份写作层（第 4 节） |
| story_hooks、world_canon | 剧本 + 事实账本 |
| 多人合流、共享奖励 | 删。单人 |

数字对比：工具 42 → 4，命令 27 → 7，数据表 26 → 6。

## 3. 与 rpg 并存：归属独占

两个插件都挂 `on_llm_request`、都重写请求、都清空工具。同一个 session 被双方接管必然打架。

**规则：一个 session 只能属于 rpg 或 art。**

- 两边的 `on_llm_request` 第一件事就是查归属。不是自己的，立刻返回，不碰请求。
- `/art start` 发现该 session 已被 rpg 占用就明确报错，反之同理。
- **只有 `reset` 释放归属**（存档已清，没有歧义）。`close` / `open` 不做——实践中没用过。

命名空间全部隔开：

| 项 | rpg | art |
|---|---|---|
| 目录 | `astrbot_plugin_agentic_RPG` | `astrbot_plugin_art` |
| 命令组 | `/rpg` | `/art` |
| Skills | `rpg-*` | `art-*` |
| 数据目录 | `astrbot_plugin_agentic_rpg/` | `astrbot_plugin_art/` |
| Web 路由 | `/api/plug/rpg-*` | `/api/plug/art-*` |
| 工具名 | 42 个 | 4 个，语义不重合 |

AstrBot 的工具名是全局的，两个插件注册同名工具会撞。art 的四个工具名与那 42 个完全不重合。

**角色卡目录共用、只读、格式不变**：两边都读 `plugins/astrbot_plugin_agentic_RPG/canonical_characters/`。卡是最重要的资产，不做会漂移的第二份副本。

## 4. 每轮怎么跑

```
玩家消息
  → 查归属（不是 art 的立刻返回）
  → 组装请求
  → 编剧（隐藏，便宜模型，按需调工具）→ 导演笔记
  → 演员（主调用，不带工具，玩家唯一看到的输出）
  → 回复玩家
  → 后台书记（不阻塞回复）：更新账本、玩家画像；换场景时归档 + 排下一个钩子
```

**编剧决定「发生什么」，演员决定「她是什么样」。** 编剧完全不碰角色的声音，角色卡只交给演员。

导演笔记只写事件层面（这一拍发生什么、推进哪个钩子、变数怎么落地），**不写台词、不写心理**。旧插件的 Director 把角色内心拆成 JSON 再让 Narrator 照着写，等于让演员照心理评估表演戏，每转述一次都丢东西。

为什么编剧要隐藏：AstrBot 的 `run_agent` 在非流式下会把中间文字当回复发出去（`astr_agent_run_util.py` 约 250-267 行），`buffer_intermediate_messages` 只是合并后一起发、不丢弃。用 `context.tool_loop_agent` 跑隐藏的一轮，再把主调用改写成不带工具的演员，是这个框架下唯一稳妥的办法。附带好处：编剧的工具调用不进对话历史，历史干净、缓存稳。

### 提示词分两层

| 层 | 内容 | 位置 |
|---|---|---|
| **写作层** `art-writing-core` | 通用写作质量，与角色无关 | system prompt 稳定前缀，缓存常命中 |
| **角色层** | canonical YAML 卡 | 场景块，随在场角色变 |

写作层从 `rpg-style-core`（311 行）抽取，约留 40%：

**抽**
- 红线 2：不代替玩家行动、感受、决策
- 红线 5：严禁标签化、机械化的感官罗列
- 篇幅来自有效 beat，不来自灌水 ← **主人要的「通用写作指导」核心**
- 感官与环境 / 句式与对白
- 场面推进的最小标准
- 玩家称呼与多人清晰度 / 角色说话人与姓名表面化 / 多人场景的镜头配额 / 角色外观描写质量
- 戏剧化不是强行转折 ← 对治剧情写太绕

**不抽**
- 红线 1（伪造状态栏、工具回执）——art 没有状态栏
- 红线 3（反未落盘生成）——依赖「工具先定事实」，art 是先写后记账，方向相反，要重写不是搬
- 红线 4、场景模式体系、RPG 长度与信息密度、RPG 探索设计、RPG 身份判断层
- **RPG 结尾开放位（强制 `[1][2][3]`）——明确删除**

### 三条硬规则

1. **提议归角色，决定归玩家。** 每轮角色或世界至少主动做一件事。玩家角色的话、承诺、情感立场、不可逆选择只能来自玩家。角色可以追问、撒娇、等待，但不能写成玩家已经答应了。取消强制编号选项，结尾停在「球在玩家手里」的那一刻。
2. **`【】` 里的内容必须执行，优先级最高。** 可覆盖一切规则，包括替玩家的角色做决定、跳时间、换场景。书记把 `【】` 当权威事实写进账本。
3. **每轮只推进一个节拍**，不跳过玩家可能想亲历的时刻。时间跳跃只在两种情况发生：玩家明说，或换场景。玩家说「继续」「你安排」时，这一拍里低风险小动作（跟着走、坐下、点单）可代劳；承诺和告白依然只属于玩家。

## 5. 编剧：只管「今天」

旧的 shaoji 模式把剧情写太绕，因为它排的是长线大纲，模型为了填满大纲会层层加反转。新编剧只有两层：

- **中期剧本**：同时最多 2-3 条，跨几天几场。例：「她在偷偷准备你的生日」「她和老朋友有个心结」。
- **短期钩子**：每场一个。例：「她想拉你去新开的花店，路上会碰到芽衣」。

规矩：
- 只写「会发生什么事」，不写「玩家会怎么回应」。
- 日常为主，偶尔起小波澜。不写反转，更不写反转套反转。
- 素材从角色自己的愿望、卡里的 `inner_tension`、日历（节日/生日）和变数牌里取。

**玩家画像由书记在后台维护，靠读反应，不靠玩家显式提要求。** 信号：哪类场景回复得长而投入、哪类一带而过；主动追问什么、主动避开什么；戏里随口说的心愿（「好想去看海」直接成为剧本种子）。

编剧读画像来**推荐**，方式是让角色提一个提议，不是由系统安排一个事件。玩家接了就展开；两次没接，这条线悄悄淡出。

## 6. 变数：代码掷，模型不能挑

检定和光锥的根本目的是「别让模型事事顺着玩家」。目的保留，数值去掉。

| 层 | 多久抽一次 | 抽什么 | 例 |
|---|---|---|---|
| 一天的底色 | 游戏内每天一次 | 她今天的状态 | 精神很好 / 有点累 / 有心事 / 特别黏人 |
| 场景牌 | 每次换场景 | 环境和第三方 | 下雨 / 人很多 / 朋友出现 / 店休 |
| 行动结果 | 每轮预抽，只在结果不确定时启用 | 成败 5 档 | 意外之喜 / 顺利 / 小波折 / 出洋相 / 落空 |
| 中期 | 编剧排剧本时 | 事件节奏 | 见第 5 节 |

- **「一天的底色」是最有效的一层**：她的态度不是被玩家这句话左右的，而是早就定好了。心情好的日子怎么都甜；有心事的日子玩家再哄也会走神。比掷骰更像真人。
- **变数可以写进角色卡**：例如「伊甸打电话邀她去彩排」。从角色自己世界里抽出来的意外，本身在给神韵加分。
- **波折是调味，不是拒绝。** 下雨打乱约会，要变成一起躲雨；要的是「世界有自己的质感」，不是「角色对你冷淡」。
- **没有甜度旋钮。** 玩家对 0-5 的数字不会有明确反应。节奏偏好用 `【最近别折腾我】` 这类话表达，书记写进账本当一条文字偏好，编剧每轮读。
- **重新生成时重抽。** 旧插件骰点按消息原文 MD5 算，原话重发点数不变；art 的变数含发送时间因子，重新生成自然换一次运气。

## 7. 关系账本：不用数字

开局由玩家声明关系前提，例如「恋人，同居第三个月」。

账本记具体的东西，分两类：

- **关于她的**：她对你的称呼、共同的回忆、说过的承诺、还没消的小别扭、送过你什么。
- **关于这局的**：玩家的节奏偏好（第 6 节）。

恋爱里「她记得我」的快乐来自这些细节，一个数字给不了。想玩攻略的玩家可以用一个粗略阶段（陌生/熟悉/暧昧/恋人），只在玩家那一方出现明确事件时推进。

**书记的硬规矩：「承诺」「告白」「答应」只在玩家自己的原话里出现时才记录。** 这样模型越权替玩家答应的事，即使出现在正文里，也不会被存成既成事实。

## 8. 角色卡三层来源

| 层 | 来源 | 谁能改 | 什么时候没 |
|---|---|---|---|
| canonical 卡 | 共用 `canonical_characters/*.yaml` | 主人手写 | 永久 |
| 生成卡 | 模型生成后落地成文件 | 主人手改 / 模型改 | `reset` 时删 |
| 路人 | 账本里一行速记 | 书记维护 | 随 session |

**解析顺序：canonical 永远赢。** 主人后来补了正式卡，生成卡自动失效，不需要任何迁移动作。

生成卡落地在 `data/plugin_data/astrbot_plugin_art/cards/<session>/<角色名>.yaml`，**格式与 canonical 完全一致**。好处三个：主人可用编辑器直接改、下一轮生效；生成得好的卡把文件移进 `canonical_characters/` 就升级；两边格式一致，rpg 也能读。

**分层注入**（旧卡大量禁令其实是在补偿「所有形态一次性全注入」这一个问题——爱莉希雅卡里 9 条禁令都在说「三套装甲别混」）：

| 内容 | 什么时候注入 |
|---|---|
| 一句话本质、3-6 个外貌锚点、她怎么想事情、习惯招式、口吻样例 | 常驻 |
| 完整外貌、当前这一套服装 | 首次登场（`cast` 工具直接返回） |
| 亲密层 | 仅 NSFW 模式 |
| 关系条目 | 对方同场时 |

**首次登场瞎编外貌**是旧插件最明显的毛病，根因是那一刻卡还没进上下文。`cast` 工具把外貌当工具结果递到手上，从机制上解决。

## 9. 验收与跑分

**跑分只测神韵**，其余（剧情推进、主动性、编剧力、写作质量）靠人主观评价——那几项本来就不该由模型打分。

跑分是**回归防线**，不是排名：`raw` 是神韵的标准线，art 只要不输就算过。

已有基线：`data/rp_bench/runs/20260928-014350+0800-shenyun/`

- 流萤 × `deepseek/deepseek-flash` × 只给 YAML 卡，6 个会话，裁判 `专用/gemini-3.1-pro-preview`
- 神韵五项平均 **4.60 / 5**：说话方式 4.83、鲜活度 5.00、整体喜爱度 4.50、角色还原 4.33、不出戏 4.33
- **噪声底 ±37 个百分点**（同配置自比胜率 67%，区间 21%–94%）。art 的盲比结果落在这个宽度内不能下结论；要分高低得加跑到 4 次。

art 落地后不要重开跑次：

```
uv run python -m scripts.rp_bench all --resume data/rp_bench/runs/20260928-014350+0800-shenyun --add-arms art
uv run python -m scripts.rp_bench pair --resume <同上> --judge 专用/gemini-3.1-pro-preview
```

需要先把 `art` 加进 `scripts/rp_bench/config.py` 的 `ARMS` 和 `RPG_ARMS`，并写 driver。`plans/shenyun.yaml` 里 pairwise 已预留，取消注释即可。

基线里发现的两个模型侧问题，art 上线后要复查是否仍在：

1. **思维链漏进正文**，64 轮里 1 轮（2%）。原文：`As Firefly, I should respond in character.` 没有标签包裹，清洗抓不到，玩家原样看到。这是 deepseek-flash 的真实行为。
2. **一处设定错误**：她说「卡芙卡……给了我名字」，卡上写的是「她为自己起名『流萤』」（firefly.yaml:72）。

跑分工具本身有一个 bug 要修：never_say 字面提取器会把禁令句「不要把"温柔"演成无底线顺从」里引号中的词单独拎出来当禁语，导致「温柔」被误判。可「温柔」在卡里到处是褒义用法，连台词都有。

另外一个不需要裁判的自测：**「继续」测试**——连续五轮只输入「继续」，看剧情有没有自己往前走。这是「我还要不要当编剧」最直接的答案。

## 10. 数据：一个库六张表

每个 session 一个 SQLite 文件。

| 表 | 存什么 |
|---|---|
| `session` | 归属、NSFW 开关、preset、关系前提、当天日期 + 今天的底色 |
| `scenes` | 地点、时间、在场者、这一场的变数牌、摘要、是否当前 |
| `cast` | 角色在本 session 的状态：卡键或路人速记、是否在场、当前形态 |
| `scripts` | 中期剧本 2-3 条 + 当前场短期钩子、状态、淡出计数 |
| `ledger` | 关系账本 + 会话偏好 |
| `memories` | 场景摘要（进 RAG） |

变数不单独建表：**今天的底色**挂 `session`，**场景牌**挂 `scenes`，**行动结果**每轮现抽现用、不落盘。

**记忆分层**：当前这一场保留原始对话；每场结束压缩成摘要存 `memories` 并进 RAG；关系账本和事实常驻上下文，**不走检索**——RAG 可能恰好没检索到「她叫你什么」，这类细节错了最伤体验。

## 11. 四个工具

| 工具 | 干什么 | 返回 |
|---|---|---|
| `change_scene` | 换场景（地点 + 时间 + 在场者） | 新场景描述 + 这一场的变数牌 |
| `cast` | 角色登场 / 离场。登场时自己判断有没有卡，没有就顺手生成并落地 | 完整外貌 + 当前状态 |
| `recall` | 翻旧记忆 | 相关场景摘要 |
| `fix_character` | 生成卡的改与删：`update`（局部修正）/ `regenerate`（整张重写）/ `delete` | 修改结果 |

**`cast` 吃掉了「生成角色」**：登场一个没有 canonical 卡的角色本来就要先生成卡，分成两个工具会让模型连调两次、可能漏第二次。一次调用闭环。

**`fix_character` 的 `update` 是局部修正，不是整张重写。** 玩家纠正一个发色，不该把性格一起换掉。旧插件 `npc_regen` 重生成会丢性格，后来才补了 `npc_flash` 增量补充——这次直接做对。

### 换错场景怎么办

以往换错场景最常见的原因是**角色提议去某地，模型就直接换了**，本质是替玩家做决定。规则写成一句话：

> 场景切换是玩家决定的结果。角色可以提议「去海边吧」，但要等玩家同意之后才换。

规则总有漏的时候，所以让代价足够低：

- **换场景不删任何东西。** 上一场原始对话保留，摘要只是额外多存一份。换错只浪费一次摘要。
- **变数牌和钩子延后生效。** 挂在新场景上，等玩家在新场景发出第一条消息才落档。玩家重新生成或回滚，自然作废。
- **让换场看得见。** 正文开头一行小字标出「📍 海边 · 傍晚」。
- **纠正走 `【】`**：`【还在咖啡店】` 直接撤回这次切换。

## 12. 七个命令

| 命令 | 干什么 | 谁用 |
|---|---|---|
| `/art start` | 开局：声明归属，选角色、世界、关系前提 | 玩 |
| `/art forget [n]` | 回滚最近 n 轮，连世界状态一起退 | 玩 |
| `/art card [名字]` | 不带名字：列出本 session 生成卡（标出已被 canonical 覆盖的）。带名字：打印全文 + 文件路径 | 玩 |
| `/art ledger` | 看她记得你什么 + 当前节奏偏好 | 玩 |
| `/art reset` | 清档，删生成卡，释放归属 | 玩 |
| `/art debug` | 场景、在场角色、剧本、变数，一次全打出来 | 排查 |
| `/art help` | 命令列表 | 玩 |

新增或改动命令时必须同步 `/art help` 的来源列表——这是 rpg 那边踩过的坑，遗漏等于新命令对玩家不可见。

## 13. 模块划分

## 14. 保留的设计原则（从 rpg 继承）

- **所有状态变化走 `state.py`**，演员只能叙述已确认的事实。
- **工具返回统一信封**（`ok` / `data` / `error`），沿用 `tool_response.py` 的模式。
- **LLM 不处理唯一标识符**，工具参数只接人类可读的名字。
- **工具操作闭环**，不依赖模型正确编排多步调用。
- **语义错误显式失败，格式错误静默修正。**
- **信息完整性优先于 token 预算**，核心叙事信息不硬截断。
- **缓存友好布局**：稳定内容进 system prompt，每轮变的只放最后一条 user message。

## 15. 北极星

> 没有插件、纯靠提示词也能玩，只是长期记忆、角色、剧情不太还原。

**插件 = 提示词的挑选器 + 外置记忆。**

所有资产都是人能直接读的文本：世界观、角色卡、关系账本、剧本、玩家画像、场景摘要。插件每轮只做两件事：挑出这一刻该给模型看的内容，把该记住的写回去。

检验方式：把某一轮组装好的提示词复制出来，贴进任何聊天窗口，都应该能接着玩。做不到，就说明插件替模型干了本该由提示词说清的事。
