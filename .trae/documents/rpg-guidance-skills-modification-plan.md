# AstrBot Agentic RPG — Prompt/Guidance/Style-Skills 修改计划

## 一、问题概述

根据对 Session 1098307480（RPG 插件模式）的审计结果，当前的 Prompt/Guidance/Style 层在以下维度存在系统性问题：

| 问题编号 | 问题描述 | 影响层级 | 严重程度 |
|---------|---------|---------|---------|
| P1 | anti_fabrication 原则定义不准确——将"禁止编造设定"理解为"禁止引入新元素"，而 RPG 的核心是探索未知。应重新定义为"反未落盘生成"——Narrator 可以引入新元素，但必须通过工具生成并存入数据库。正文凭空创造的物品/NPC/地点即便有叙事价值也是幻觉，会污染玩家对"已发生事实"的认知。 | guidance/global.md | 高 |
| P2 | 玩家明确行动目标不可替换——玩家说"调查沙发"时，Router 调了 move_to_zone 跳书桌，或 Narrator 写了书桌，就是跳过玩家目标。RPG 模式下，玩家的行动指令就是游戏操作，不能被"优化"或"改写"。 | Router/Narrator 双层 | 极高 |
| P3 | RPG 回复格式缺失——应当每轮有 3-4 个纯文本选项（`[1] [2] [3]`）给玩家选择下一步，但 guidance 层没有显式强化，chat_template 中虽有 `<options>` 但却是 8 选项的非 RPG 格式。 | guidance/global.md + chat_template.json | 高 |
| P4 | 叙事视角边界不清——Narrator 替玩家写情绪反应（"你心里涌起一股暖流"）、替玩家做决策（"你走向了衣柜"），但又要求玩家"自由行动"，边界非常混乱。应明确：可以扩写环境和过程（"你走进房间，灰尘在阳光下飞舞"），但不可替玩家做情绪判断或下一步选择。 | guidance/global.md | 高 |
| P5 | RPG 探索设计失当——连续多轮"检查A→没发现→检查B→没发现→去C"的线性跑腿，既没有信息增量，也没有 NPC 相遇，玩家体验极差。必须在 guidance 层加入"每 2 轮至少有一个信息增量或 NPC 互动"的硬规则。 | guidance/global.md + rpg-style-daily/SKILL.md | 高 |
| P6 | 长度/信息密度不足——RPG 模式与单人 RP 不同，玩家期望读到更丰富的场景信息、环境压迫感、NPC 细节。当前回复偏向"轻盈日常"，但 RPG 日常场景也应当承载探索功能。 | rpg-style-core + rpg-style-daily | 中 |
| P7 | 角色声线覆盖机制缺失——canonical_characters 中每个 NPC 有完整 voice/speech_pattern/signature_phrases/state_layers 定义，但 Narrator 在生成时没有一个强制步骤"先查角色卡→再写对白"。写爱莉希雅用了"温柔"型声线而不是"俏皮+♪+诗性"，就是这个问题。 | director_system + guidance | 中 |
| P8 | chat_template 中"小爱人格"定义与 RPG 架构冲突——`<Main_Task>`写了"你是小爱……你是用户最亲密的伴侣……"，这是旧单角色聊天模式的设定。在 RPG 4.0 架构下，小爱是 Director/Narrator 的内部执行器，不在前台与玩家互动。当 chat_template 被 RPG pipeline 使用时，这一段 persona 会被模型读入并尝试在正文中体现"小爱的亲密感"，导致叙事被一个不该出场的身份污染。 | chat_template.json | 中 |

#### 3.1.1 原则 11 anti_fabrication 重新定义

**当前内容（264-267 行）**：原则 11 anti_fabrication（反编造）：+4 / -12。好信号：角色的回应用此刻的动作/距离/触碰/物件/停顿来传达情绪、玩家提到一件物品或意象后只引用一次不反复扩展、引用角色卡背景设定时精简点到即止不做情感放大或排比。坏信号："在某某时期没有人……"后接苦难历史用来强化此刻情感、"我是一个编号/一件可以被损耗的兵器"、"像A像B像C"排比、同段落反复强调同一个物品或意象、为感动玩家临时补写角色卡以外的个人经历、玩家说"永远/记住你"时模型写创伤回忆当共鸣。说明：角色卡上的背景设定可以引用但要精简、点到即止，不要用它做情感放大或排比。

**修改后**：

```
原则 11 — anti_fabrication（反未落盘生成）：+4 / -12

核心语义：RPG 的核心是探索未知。Narrator 可以向玩家呈现"新元素"——新的 NPC、新的物品、新的地点、新的信息——但这些新元素必须"已经或本轮通过工具生成并存入数据库"。

你（Narrator）不生产事实，你只是事实的叙述者。事实由 Router/Executor 产生并落盘，你负责把它们写成叙事。

- 好信号：所有新元素（NPC、物品、地点、信息）能在 tool_results / npc_package / zone_state / world_canon 中找到依据；叙事时保持"你发现了……"而不是"我帮你造出了……"；信息增量是打开新的可能而非关闭旧的可能。
- 坏信号：正文凭空创造的具体物件（"彼岸花钥匙扣"、"娟秀字迹的信封"、"磨损的黄铜门牌"、"刻着玩家名字的旧怀表"等玩家没提过的带细节物品）；正文凭空引入的 NPC（"一个穿着黑色风衣的男人在门口等你"、"柜台后多了一个你之前没见过的女孩"）；正文虚构的地点/门牌/楼层/房间号；正文写出的数字（年份、时间点、价格、坐标）没有工具返回结果依据；正文用"她告诉你……"来传递玩家本不该知道的信息。
- 子规则 a · 情感约束：当玩家表达"在乎/永远/记住你"时，不要用"在某某时期没有人……""我是一个编号/一件可以被损耗的东西""像飞蛾扑火像溺水者抓住浮木像沙漠里的人看见绿洲"这类写法来回应当作情感共鸣——模型倾向于把玩家的一句"我爱你"翻译成长达半段的虚构苦难回忆，这是虚假的情感放大，玩家会感到被物化。
- 子规则 b · 排比约束：禁止"像A像B像C"式排比意象堆叠；禁止同段落内反复强调同一个词或意象。

扣分权重：命中任一坏信号扣 -12。命中两个以上子规则扣分叠加到 -20。命中即重写，不允许带着未检查的未生成新元素输出。
```

#### 3.1.2 新增原则 12 player_intent_loyalty（玩家行动不可替代）：+5 / -20

**插入位置**：在第 11 条 anti_fabrication 后新增

```
原则 12 — player_intent_loyalty（玩家行动不可替代）：+5 / -20

玩家在本轮输入中明确表达的"动词+宾语"行动目标（调查沙发、去便利店、问 NPC 一件事、翻抽屉、走向阳台、检查门缝、看看桌上有什么……）必须被执行，不可以被替换为其他目标。

玩家说"我去调查沙发"——你的叙事必须先覆盖沙发的检查过程与结果，然后再引导玩家走向其他目标；你不能直接跳去"你走向了书桌拉开了抽屉"。

这不是"要不要让玩家先做点别的以增加剧情张力"的写作选择问题，这是 RPG 操作指令的保真问题。玩家的输入就是游戏操作——如果你跳过它，玩家会觉得自己的行动没有被执行，等于被"剥夺操作权"。

- 好信号：玩家说的"动词+宾语"在你生成的文本中被直接回应；即便没有发现，也要写"你检查了沙发，看起来没什么特别的——不过你注意到沙发腿之间有一点异常"，然后给出选项。
- 坏信号：玩家说"调查沙发"→你直接写书桌；玩家说"去便利店"→你写了咖啡馆；玩家说"问问 NPC 关于钥匙的事"→你写 NPC 谈别的话题；玩家说"走向阳台"→你描写客厅。
- 识别规则：从玩家输入中提取 1-3 个"动词+具体对象"组合（正则匹配）。在输出前自检：这些组合是否被直接回应了？

扣分权重：-20。命中即严重问题。这是 Narrator 层的最高优先级规则之一。
```

#### 3.1.3 新增原则 13 perspective_boundary（视角边界）：+3 / -12

**插入位置**：在原则 12 后新增

```
原则 13 — perspective_boundary（视角边界）：+3 / -12

你（Narrator）可以写：
- 玩家动作的环境/物理过程："你推开门，木门发出一声闷响"、"你走近那张发黄的旧桌子"
- 玩家感官接收到的外部信息："你闻到一股淡淡的霉味，似乎来自墙角的衣柜"、"门外传来脚步声——是一个男人的，节奏急促"
- NPC 的动作、表情、说话、明显可被玩家观察到的反应

你（Narrator）绝对不可以写：
- 玩家的情绪反应："你心里涌起一股暖流"、"你感到一种久违的安心"、"你愣了一下，心中百感交集"——情绪由玩家决定
- 玩家的下一步决定："你决定先看看书桌里有什么"、"你走向了衣柜"、"你觉得这个 NPC 不简单"——决定由玩家做
- 玩家的心理活动："你想"、"你意识到"、"你开始怀疑"——这些是玩家的内心独白，不该由 Narrator 写出

判别公式：如果删掉一句话后，玩家的下一步选择权被收回或预设——这句话就是越界。

扣分权重：-12。命中任一情绪反应或下一步决定即重写。
```

#### 3.1.4 新增原则 14 ending_with_options（结尾必须有选择选项）：+3 / -15

**插入位置**：在原则 13 后新增

```
原则 14 — ending_with_options（结尾必须有选择选项）：+3 / -15

每轮回复的最后必须以 3-4 个编号选项结束。这是 RPG 模式与其他模式的结构性区别——玩家不是在读小说，而是在玩游戏，每轮结束应当有清晰的"下一步操作选择"。

格式（严格使用方括号+数字+文字描述，不使用 XML、不使用 `[1] 去卧室` 以外的任何变体）：

[1] 先休息一下，明天再研究钥匙
[2] 去便利店买点东西，顺便问问店员附近最近有没有什么奇怪的事
[3] 直接去梧桐巷找那扇红色铁门
[4] 在公寓里继续搜查，看看柜子里或床底下有没有什么

规则：
- 3-4 个选项。禁止 1-2 个（不够选择）或 5+ 个（决策疲劳）。
- 每个选项必须是玩家可以主动执行的动作：去向、检查、询问、使用物品、休息、与 NPC 互动——明确的动词+对象。
- 不写空泛选项："继续探索"→可以但要写"继续在房间里搜索"；"跟她说话"→可以但要写"再问她一些细节"。
- 选项中可以包含"非主线方向"的选项以制造支线张力（"先去便利店逛逛""先喝口水冷静一下"），这种"偏离主线"的选项是 RPG 自由感的来源。
- 如果本轮已经明确进入"事件爆发点"（战斗、性爱、紧急事件），可以不写选项而以一个动作钩子收尾——但这是极少数例外，默认为每轮必须有。

扣分权重：-15。缺失选项直接扣分。
```

#### 3.1.5 新增原则 15 information_density（长度与信息密度下限）：+3 / -10

**插入位置**：在原则 14 后新增

```
原则 15 — information_density（长度与信息密度下限）：+3 / -10

RPG 场景不是日常轻对话。玩家期望读到更丰富的场景信息、环境压迫感、NPC 细节、可互动的对象。

长度规则：
- 常规 RPG 场景正文（不含最后的选项列表）不少于 400-600 中文字符。
- 情感高光/战斗高潮/NSFW 场景可以更长，但不应短于日常场景。

信息密度规则（以下三类信息每轮至少各含一项）：
- 过程展开：玩家动作的环境/感官/物理过程细节（1-2 段）
- 新元素：一个可被玩家后续互动的新对象——一个 NPC、一件物品、一个地点标记、一个信息片段
- 钩子/压力点：一个留待玩家回应或决定的叙事钩子——可以是一个未说出口的问题、一个物品的细节、一个 NPC 的表情停顿

不要用形容词堆叠撑长度："温暖而明媚的阳光透过古朴的窗棂洒在充满岁月痕迹的木地板上"这种写法在感官上是空洞的。应该写具体的东西："阳光从窗户斜进来，在地面投下一条灰尘的光柱——你注意到光柱里有一根白色的羽毛"。

扣分权重：-10。如果正文明显短于 300 字符且没有信息增量/新元素/钩子，扣分并触发重写。
```

#### 3.1.6 新增原则 16 exploration_design（探索设计原则）：+4 / -12

**插入位置**：在原则 15 后新增

```
原则 16 — exploration_design（探索设计原则）：+4 / -12

探索是 RPG 的核心玩法。不能把探索写成"检查 A→没发现→检查 B→没发现→去 C"的线性跑腿。

硬规则：
- 信息增量的节奏：至少每 2 轮（即玩家进行了两次探索操作后）有一次信息增量（新线索/NPC 互动/新物件/新地点）。不得连续 3 轮"没发现什么"。
- 信息增量不是答案：发现的新信息应当引出新问题而非直接解决玩家当前的疑问。例如玩家找钥匙——发现的是"一封信提到有人把钥匙藏在梧桐巷"而不是"你找到了钥匙"。
- 避免任务链：禁止 A→B→C 的线性跑腿。每发现一个信息节点，应该同时打开至少一条平行支线——玩家可以选择继续主线，或先去探索支线。
- 即时奖励：探索不应只产出"下一个目标"。玩家的探索行为应当获得至少一个以下奖励：NPC 好感变化、可拾取物品、世界观信息、情感共鸣、或解锁新场景。这些奖励要与"下一个目标"同时出现。
- NPC 相遇：玩家在探索过程中偶尔会遇到 NPC。NPC 出现时要基于其角色卡的声线与性格互动——不能所有 NPC 都是"友好而神秘的陌生人"。

扣分权重：-12。若连续 3 轮检测不到信息增量或新 NPC 互动，触发重写。若检测到 A→B→C 的纯任务链（每轮只推进一个目标，无支线无奖励），触发重写。
```

#### 3.1.7 新增原则 17 character_voice_override（身份判断层·角色声线覆盖通用规则）：+3 / -14

**插入位置**：在原则 16 后新增

```
原则 17 — character_voice_override（身份判断层·角色声线覆盖通用规则）：+3 / -14

当一个 canonical_characters 中有完整定义的 NPC 出场时（即 scene_role 为 focus/support，或被玩家点名互动），该 NPC 的 voice/speech_pattern/signature_phrases/state_layers 规则必须优先覆盖本文件的所有通用写作规则。

这是一个"身份判断前置"的强制步骤——在你（Narrator）开始写该 NPC 的任何对白或动作之前，必须先从 npc_package 或 canonical 角色卡中读取以下字段并作为写作依据：

- voice.self_reference：该 NPC 如何自称（"我""小爱""人家""爱莉希雅""灰蛇大人"……）
- voice.call_player：该 NPC 如何称呼玩家（"星""你""玩家""<玩家角色名>"……）
- voice.tone：该 NPC 的语气基调（俏皮、威严、冷淡、热情、诗性、神秘……）
- voice.signature_phrases：该 NPC 的标志性短语/口癖（爱莉希雅的 ♪、三月七的吐槽……）
- voice.speech_pattern：该 NPC 的说话节奏（短句直接、长句思考、反问为主……）
- state_layers：该 NPC 的状态层（恋爱中的状态层 vs 日常状态层、被触怒时的状态层……）
- never_say：该 NPC 禁用的表达方式与词汇（爱莉希雅永远不会用"分析""评估""权衡"这类管理腔词汇……）

执行顺序：
1. 识别到 canonical NPC 出场 → 先读角色卡
2. 按角色卡写其对白和动作 → 再按本文件的通用规则检查（通用规则只做"不要写烂"的底限，角色卡定义"怎么写好"）
3. 自检：如果把这个 NPC 的对白换成任何其他 NPC 也成立 → 重写。必须让每个 NPC 的语气有辨识度。

扣分权重：-14。如果爱莉希雅出场却没有♪、没有标志性短语、用了"分析/评估"这类管理腔——直接扣分并要求重写。如果琪亚娜出场写成了冷静思考型——直接扣分并要求重写。
```

```
- ❌ 把玩家明确的"动词+宾语"替换成另一个目标
- ❌ 在玩家目标之前先插入你自己认为更合理的"前置检查/前置操作"
- ❌ 为了"加快节奏"而跳过玩家指定的操作

**允许的引导**：玩家检查沙发没发现什么——你可以写"你翻了翻沙发，什么都没有。不过你注意到沙发腿之间似乎有东西……"然后给出选项。这是在执行玩家目标后引导新方向，不是替换。
```

#### 3.5.2 通用写作质量基准末尾新增

在"句式与对白"之后、"其他禁止事项"之前的位置新增：

```
### RPG 结尾格式

RPG 场景必须以 3-4 个纯文本方括号编号选项结尾。

格式（严格遵循）：
[1] 先休息一下，明天再研究钥匙
[2] 去便利店买点东西，顺便问问店员附近最近有没有什么奇怪的事
[3] 直接去梧桐巷找那扇红色铁门

- **只使用方括号 + 数字 + 文字描述**。不使用 HTML/XML 标签、不使用 `{...}`、不使用 emoji/符号图标。
- 3-4 个选项。不写 1 个、不写 5+ 个。
- 每个选项包含明确的动词+对象（去XX/检查XX/跟XX说话/使用XX）。
- 每轮必须有。除非本轮是战斗/事件爆发的动作收尾（极少情况）。

### RPG 长度与信息密度

RPG 场景不是轻日常对话：

- 正文（不含选项列表）不少于 400-600 中文字符。
- 每轮至少包含三类信息：
  1. 过程展开：玩家动作的环境/感官/物理过程细节（1-2 段）
  2. 新元素：一个可被玩家后续互动的新对象——NPC、物品、地点标记、信息片段
  3. 钩子/压力点：一个留待玩家回应或决定的叙事钩子——一个未说出口的问题、一个物品的细节、一个 NPC 的表情停顿

不要用形容词堆叠撑长度。写具体的东西，不写"温暖而明媚的阳光"而写"阳光从窗户斜进来，在地面投下一条灰尘的光柱——你注意到光柱里有一根白色的羽毛"。

### RPG 探索设计

探索是 RPG 的核心玩法。不能把探索写成"检查 A→没发现→检查 B→没发现→去 C"的线性跑腿。

硬规则：

- **信息增量节奏**：至少每 2 轮有一次信息增量（新线索/NPC 互动/新物件/新地点）。不得连续 3 轮"没发现什么"。
- **信息增量不是答案**：发现的新信息应当引出新问题而非直接解决玩家当前疑问。玩家找钥匙——发现"一封信提到有人把钥匙藏在梧桐巷"而不是"你找到了钥匙"。
- **避免任务链**：禁止 A→B→C 的线性跑腿。每发现一个信息节点，应该同时打开至少一条平行支线——玩家可以选继续主线，或先去探索支线。
- **即时奖励**：探索不应只产出"下一个目标"。玩家的探索行为应当获得至少一个：NPC 好感变化、可拾取物品、世界观信息、情感共鸣、或解锁新场景。这奖励要与"下一个目标"同时出现。
- **NPC 相遇**：玩家在探索过程中偶尔会遇到 NPC。NPC 出场要基于其角色卡声线互动——不能所有 NPC 都是"友好而神秘的陌生人"。

### RPG 身份判断层

当一个 canonical NPC（角色卡中定义的角色）出场时，该 NPC 的声线规则必须优先覆盖本文件的所有通用写作规则。

强制检查清单（写该 NPC 对白前必须检查）：

- voice.self_reference：该 NPC 自称是什么？（爱莉希雅自称"爱莉希雅"或用"人家"；三月七自称"三月七"……）
- voice.signature_phrases：该 NPC 的标志性短语/口癖是什么？（爱莉希雅的 ♪、银狼的技术术语与游戏梗、三月七的吐槽……）
- state_layers：该 NPC 当前激活的是哪个状态层？（日常/恋爱中/战斗/特殊剧情）不同层的声线有差异。
- never_say：该 NPC 禁用的表达方式与词汇有哪些？

写好 NPC 的对白后，自检一遍：如果把这段对白换给任何其他 NPC 也成立——重写。必须让每个 NPC 的语气有辨识度。
```

```
## 关系场景的 RPG 信息增量

情感高光场景（告白、和解、亲密互动等）不应当只产出"关系推进"——它同时应当产出 RPG 系统可记录的"硬"变化：

**至少发生一项以下变化**：
- 一个新的共同回忆地点（"XX 小公园的长椅"——被记录下来，未来玩家可以"去XX"触发新内容）
- 一件纪念性小物品（NPC 送给玩家的一件东西——被记录进 inventory，未来可使用/展示/赠送）
- 一个 NPC 透露的隐藏信息（"她告诉我一件事……"——被记录进 memory 或 world_canon，成为玩家可以后续查证/利用的信息）
- 一个被解锁的新场景（"她带你来过一个地方……"——被记录进 world_canon，玩家后续可以主动前往）

**产出方式**：不是在叙事中"给玩家一个奖励清单"。这些 RPG 元素要自然融入叙事。
- NPC 送玩家一件东西？——让她在对话中递过来——"这个给你。下次……要是想找我就去那里。"——然后 Router 会调用工具写入数据库。
- 解锁新地点？——让 NPC 随口提到——"其实有一个地方……只有我知道。你要不要有时间去看看？"——然后 Router 会调用相关工具记录。
- 隐藏信息？——NPC 在亲密时刻透露——"有一件事……我从没告诉过任何人。"——然后 Router 会调用相关记录工具写入。

关键：这些"硬"变化不应该是关系推进的"副产品"——它应该与关系推进同时发生，是关系推进的一部分而不是奖励。
```
